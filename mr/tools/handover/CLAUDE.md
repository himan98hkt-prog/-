# 피아노학원 자동 반주(MR) — 이 저장소에서 일할 때

악보(MusicXML·MIDI)를 넣으면 **곡의 화성을 자동 분석해** 오케스트라 반주를
만드는 프로그램입니다. 학원 관리 프로그램과 **따로 파는 별도 제품**입니다.

**전 과정이 로컬 연산입니다. 외부 API 호출 0회.**

---

## 무엇을 파는 물건인가

1. 악보를 넣으면 **반주가 나오는 것**
2. 발표회 당일 **안 터지는 운영 도구**

이 둘이 아니면 이 제품의 일이 아닙니다. 한 번 실제로 범위를 넘은 적이 있어서
적어 둡니다 — 아이가 며칠 연습했는지를 학부모에게 보고하는 기능을 만들었다가
**되돌렸습니다.** 기능이 고장나서가 아니라 그건 학원 관리의 일이기 때문입니다.
새 기능을 붙이기 전에 위 두 줄에 들어가는지 먼저 보세요.

---

## 절대 하지 말 것 (개발지시서 3장 — 원문 그대로)

1. **LLM에게 MusicXML/MIDI를 직접 생성시키지 말 것.** 마디 수가 안 맞고 마디
   안 음가 합이 깨진다. LLM은 "편곡 지시(JSON)"까지만, 실제 음표 배치는
   결정론적 코드가 한다.
2. **Suno / Lyria 같은 생성형 오디오를 반주 엔진으로 쓰지 말 것.** 원곡의
   조성·마디 수·템포 격자에 맞출 수 없고, 같은 프롬프트도 매번 결과가 다르다.
3. **"PDF 넣으면 바로 완성"을 약속하지 말 것.** 확인 화면 없이는 32마디에
   2~6마디가 틀린다.
4. **연주 음원만으로 반주를 만들지 말 것.**
5. **오디오 파일을 카탈로그로 저장하지 말 것.** MIDI를 저장하고 필요할 때
   렌더한다.
6. **현대 교재·대중곡을 카탈로그에 넣지 말 것.**

> 1번이 제일 자주 유혹합니다. "악보가 없으니 하나 만들어 넣자"가 바로 그것이고,
> **실제로 그 상황이 여러 번 옵니다** (콩쿨 54곡의 악보가 아직 없습니다).
> 지어내지 마세요. 없으면 없다고 두고, 악보가 들어올 자리만 만들어 두세요.

### 블랙리스트 (절대 금지 — 예외 없음)

현대 교재(바스티앙 · 알프레드 · 피아노 어드벤처) · 이루마 · 지브리 · 디즈니 ·
드라마 OST · K-pop 편곡 · 저작권 있는 콩쿨 지정 창작곡.

`piano_mr/repertoire.py` 가 코드로 막고 있습니다. 목록을 느슨하게 하지 마세요.

## 타협 불가 세 가지

**① 오프라인 재생** (지시서 모듈 ⑤-1). 발표회장 와이파이는 믿을 수 없습니다.
서버가 죽어도 반주가 나와야 합니다. 그래서 웹폰트를 안 쓰고, 플레이어 이미지를
파일이 아니라 코드 안에 SVG 로 둡니다 — `sw.js` 의 `SHELL_FILES` 에 줄이 늘면
**그중 하나만 빠져도 `cache.addAll` 이 전부 거부해 오프라인이 통째로 죽습니다.**
온라인에서는 멀쩡하고 비행기 모드에서만 안 뜨는 고장입니다.

**② 반주만 나온다.** 출력에 원곡 피아노가 섞이면 아이가 녹음된 피아노와 겹쳐
치게 되어 MR 이 아니라 감상용 데모가 됩니다. 확인용은 `--mix full`.

**③ 올린 PDF 를 서버가 들고 있지 않는다** (지시서 7장). MusicXML 이 오는 순간
지웁니다. **실패했을 때도 지웁니다** — 실패한 작업이 PDF 를 안고 쌓이는 쪽이
더 위험합니다.

## 모르면 거절한다 — 이 제품의 기본 태도

세 군데가 같은 원칙으로 쓰여 있습니다. **추측해서 통과시키지 마세요.**

| 어디 | 무엇을 | 모를 때 |
|---|---|---|
| `piano_mr/provenance.py` | 악보 **입력본**의 라이선스 | `unknown` → **판매용에서 뺀다** |
| `piano_mr/repertoire.py` | 작곡가 사망연도 | 만료 안 된 것으로 본다 |
| `piano_mr/midifile.py` | MIDI 의 박자표 | **거절한다** (4/4 로 가정 금지) |
| `piano_mr/pdf.py` | PDF 쪽수 | 거절한다 (쪽이 과금 단위) |

### 권리는 세 겹입니다

① **곡**(작곡가, 사후 70년) ② **판본**(출판사 편집) ③ **입력본**(그 파일을
컴퓨터에 쳐 넣은 사람). ③이 실제로 문제가 되는 자리입니다 — **곡이 만료돼도
그 파일에 붙은 약정은 따로 돌아갑니다.**

`sellable` 은 `commercial` 과 다릅니다. `CC BY-ND` 는 상업적 사용을 허용하면서
2차적 저작물을 금지하는데, **반주를 붙이는 것이 바로 그 2차적 저작물입니다.**

> **유료 판매 착수 전 저작권 전문 변호사 1회 상담은 필수 비용으로 잡을 것.**
> (지시서 7장 마지막 줄) 코드의 출처 검사는 그 상담을 **대신하지 않고 준비**합니다.

## 손대면 안 되는 것

**화성 엔진의 상수** (`piano_mr/harmony.py`). 지시서 12장이 "실패를 거쳐 나온
값"이라고 한 것들이고, 테스트가 못 박고 있습니다. 정확도 99.5% 는 네 번의
구성 변경 끝에 나온 값입니다 — 상수를 만지면 그 기록이 무의미해집니다.

**`mr` 밖을 참조하지 않기.** 이 제품은 혼자 서야 합니다.
`tests/test_standalone.py` 가 `import ..` 를 잡습니다.

## 어떻게 돌리나

```bash
python3 -m pytest                       # 전체
python3 bench.py --stages               # 화성 정확도 표
python3 seed_catalog.py                 # 연습곡 넣기 (처음 한 번)
python3 serve.py                        # http://127.0.0.1:8765

# 브라우저 검사 — 세 배치를 다 봐야 한다
pip install playwright && python3 -m playwright install chromium
python3 tools/player_check.py                              # 서버
python3 catalog_cli.py package /tmp/pkg
python3 tools/player_check.py --static /tmp/pkg            # 정적 루트
python3 tools/player_check.py --static /tmp/pkg --subfolder  # 도메인/반주/
```

**브라우저 검사를 건너뛰지 마세요.** 이 제품에서 크게 틀린 것들은 전부
파이썬 테스트가 아니라 브라우저에서 잡혔습니다 — 영상이 영영 안 뜬 것,
고친 화성이 폰에 안 간 것, 하위 폴더에서 404 가 난 것.

mp3·wav 를 구울 때만 필요합니다 (평소 개발에는 없어도 됩니다):

```bash
sudo apt-get install fluidsynth ffmpeg fluid-soundfont-gm   # 맥: brew install fluid-synth ffmpeg
```

tools/

## 글을 쓸 때

원장님이 읽는 글에 **개발 용어를 쓰지 않습니다** (`npm` `pip` `API` `localhost`
`git`). 테스트가 막고 있습니다. 주석과 문서는 **무엇을 했는지가 아니라 왜
그렇게 했는지**를 적습니다 — 특히 "이렇게 안 하면 무엇이 조용히 깨지는지".
