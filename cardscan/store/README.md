이 폴더에 플레이스토어에 필요한 것을 모두 만들어 두었습니다. 아래 순서대로 따라 하면 됩니다.

| 파일 | 용도 |
|---|---|
| `listing.md` | 앱 이름·설명·출시 노트 (한국어·영어) — 그대로 복사 |
| `play-console-answers.md` | "앱 콘텐츠" 설문 답변표 (데이터 보안·콘텐츠 등급 등) |
| `testers.md` | 비공개 테스트 12명 모집 문구·테스터 안내문·프로덕션 신청 답변 예시 |
| `graphics/` | 아이콘 512, 피처 그래픽 1024×500, 휴대폰 스크린샷 6장 |

> 이 가이드는 2026년 10월 기준 구글 플레이 정책으로 작성했습니다. 구글이 수시로 바꾸므로 콘솔 화면 안내가 다르면 콘솔을 따르세요.

## 0단계 — 수익화 방식 먼저 정하기 ⚠️

**한 번 "무료"로 올린 앱은 나중에 "유료"로 바꿀 수 없습니다.** (유료 → 무료는 가능)
앱을 만들 때 고르는 무료/유료가 영구적이므로 먼저 정해야 합니다.

| 방식 | 장점 | 단점 | 추가 개발 |
|---|---|---|---|
| **유료 앱** (예: 4,900원 1회) | 가장 간단, 바로 출시 가능 | 무료 경쟁 앱이 있어 다운로드 수가 적음. 48시간 내 환불 가능 | 없음 |
| **무료 + Pro 1회 구매** (인앱 결제) | 다운로드가 많고 써 본 사람이 삼 | 결제 기능 개발·테스트 필요 | 결제 연동 필요 |
| **무료 + 월 구독** | 꾸준한 수익 | 이용자 거부감, 구독 관리 정책이 더 까다로움 | 결제 연동 필요 |
| 광고 | 이용자 부담 없음 | 업무 앱과 안 어울림, 데이터 보안 답변·광고 ID 등 추가 | 광고 SDK |

**권장**
- **빠르게 팔아 보고 싶다면 → 유료 앱(3,900~5,900원)으로 시작.** 이 폴더의 자료 그대로 바로 출시할 수 있습니다. 판매가 약하면 나중에 무료로 바꾸고 Pro 결제를 붙일 수 있습니다.
- **오래 키울 서비스라면 → "무료 + Pro 1회 구매"** 가 경쟁력이 가장 좋습니다. 예: 무료는 명함 30장·연락처 저장, Pro 는 무제한·구글 시트/CRM 연동·엑셀 내보내기·여러 장 한 번에. 결제 기능(Google Play 결제)은 요청하시면 만들어 드립니다. 이 경우 지금은 **무료**로 만들어도 됩니다(인앱 결제는 언제든 추가 가능).

### 판매 전에 꼭 할 것 (돈 받는 앱이라서)
1. **결제 프로필(판매자 계정)**: 플레이 콘솔 → 설정 → 결제 프로필. 은행 계좌·세금 정보 등록. 이게 있어야 유료 앱·인앱 결제를 만들 수 있습니다.
2. **수수료**: 구글이 매출의 15%(연 매출 100만 달러까지, 콘솔에서 "15% 서비스 수수료 등급" 등록 필요)를 가져갑니다.
3. **세금·사업자**: 판매 수익은 소득 신고 대상입니다. 개인이 계속 판매하면 **사업자등록·통신판매업 신고**가 필요할 수 있으니 세무사나 국세청(126)에 확인하세요. (이 가이드는 법률·세무 조언이 아닙니다)
4. **주소 공개**: 수익화하는 개인 개발자는 플레이 앱 페이지에 연락처·주소가 공개될 수 있습니다. 집 주소가 싫다면 사업장 주소를 쓰세요.
5. **⚠️ 소스 코드·설치 파일이 지금 공개 상태입니다**: 이 GitHub 저장소는 공개(Public)라서 누구나 소스를 받아 직접 빌드할 수 있고, Releases 의 APK 도 누구나 무료로 받을 수 있습니다. 유료로 팔려면
   - 저장소를 **Private** 로 바꾸세요 (Settings → General → Danger Zone → Change visibility). Actions 빌드는 Private 에서도 무료 한도 안에서 계속 됩니다.
   - 단, **무료 GitHub 계정은 Private 저장소에서 GitHub Pages 를 못 씁니다** → 아이폰 웹앱·개인정보처리방침 주소가 꺼집니다. 해결책: (a) GitHub Pro(월 4달러) 또는 (b) 개인정보처리방침만 별도 공개 저장소/구글 사이트에 올리기. 원하시면 바꿔 드립니다.
   - 공개 Releases 의 무료 APK 배포도 멈춰야 합니다(요청하시면 워크플로를 바꿔 드립니다).

## 1단계 — GitHub Pages 켜기 (개인정보처리방침 주소)

플레이는 연락처·카메라를 쓰는 앱에 **열리는 개인정보처리방침 주소**를 요구합니다. 이미 자동 배포되고 있고, 켜기만 하면 됩니다.

1. https://github.com/himan98hkt-prog/-/settings/pages
2. Source: **Deploy from a branch** → Branch: **gh-pages** / **(root)** → **Save**
3. 1~2분 뒤 https://himan98hkt-prog.github.io/-/privacy.html 이 열리는지 확인

## 2단계 — 구글 플레이 개발자 계정

1. https://play.google.com/console 접속 → 구글 계정으로 로그인 (업무용 Gmail 권장)
2. 계정 유형: **개인** (사업자가 있고 D-U-N-S 번호가 있으면 "조직" — 조직 계정은 12명·14일 테스트가 면제됩니다)
3. 등록비 **25달러(1회)** 결제
4. **본인 인증**: 신분증(주민등록증·운전면허증·여권) 사진, 이름·주소 (결제 카드 명의와 같아야 함)
5. **휴대폰 번호 인증**, 그리고 **안드로이드 실기기 인증**: 안내에 따라 휴대폰에 "Play Console" 앱을 설치해 로그인
6. 개발자 이름: 스토어에 표시되는 이름 (예: "명함스캔" 또는 본인/상호)

## 3단계 — 업로드 키 등록 (GitHub Secrets)

플레이는 개발자 본인의 키로 서명된 파일만 받습니다. 키는 미리 만들어 두었고, **`GitHub-Secrets-붙여넣기.txt`** 와 **`cardscan-upload.jks`** 파일로 따로 전달했습니다(보안상 저장소에는 넣지 않았습니다).

1. https://github.com/himan98hkt-prog/-/settings/secrets/actions → **New repository secret**
2. 텍스트 파일에 적힌 4개(Name / Secret)를 하나씩 붙여 넣어 저장
   - `CARDSCAN_UPLOAD_KEY_ALIAS`, `CARDSCAN_UPLOAD_STORE_PASSWORD`, `CARDSCAN_UPLOAD_KEY_PASSWORD`, `CARDSCAN_UPLOAD_KEYSTORE_BASE64`
3. 두 파일은 USB·개인 클라우드 등 **두 곳에 보관**. 남에게 보내지 마세요.
   - "Play 앱 서명"을 쓰므로 업로드 키를 잃어버려도 콘솔에서 재설정을 요청할 수 있습니다.

## 4단계 — 업로드용 AAB 만들기

1. 앱 코드가 바뀌어 올라갈 때마다 **자동으로 빌드**됩니다. 3단계(Secrets) 를 한 뒤 새로 빌드하려면: https://github.com/himan98hkt-prog/-/actions → 왼쪽 **"명함스캔 플레이스토어 AAB"** → 가장 최근 실행 → 오른쪽 위 **Re-run all jobs**
   (작업 브랜치가 기본 브랜치에 합쳐진 뒤에는 같은 화면의 **Run workflow** 버튼으로도 실행할 수 있습니다)
2. 20분쯤 뒤 초록 체크 → 실행 화면 맨 아래 **Artifacts → cardscan-play-aab** 다운로드 → 압축을 풀면 `cardscan-play-v1.0.0-XXXXXX.aab`
   - 파일 이름이 `TEST-ONLY-업로드금지-...` 로 나오면 3단계 Secrets 가 빠진 것입니다. 이 파일은 올리지 마세요.
3. 플레이용 패키지 이름은 **`io.github.himan98hktprog.cardscan`** 입니다 (영구, 바꿀 수 없음).
   지금 직접 설치해 쓰는 APK(`com.cardscan.app`)와는 **다른 앱**으로 설치됩니다. 기존 명함은 설정 → 백업 파일 만들기 → 새 앱에서 복원으로 옮기세요.

## 5단계 — 콘솔에 앱 만들기 · 정보 입력

1. 콘솔 → **앱 만들기**
   - 앱 이름: `명함스캔 - 명함 인식·연락처 자동 저장`
   - 기본 언어: **한국어 – ko-KR**
   - 앱 또는 게임: **앱** / 무료 또는 유료: **0단계에서 정한 대로** ⚠️
   - 선언 2개 체크 (개발자 프로그램 정책, 미국 수출법)
2. 대시보드의 **"앱 설정"** 할 일을 차례로:
   - **앱 콘텐츠** → `play-console-answers.md` 표대로
   - **스토어 등록정보** → `listing.md` 복사 + `graphics/` 업로드
   - **앱 카테고리·연락처 세부정보** → 비즈니스, 이메일
3. 가격(유료일 때): 수익 창출 → 제품 → 앱 가격 → 예: 4,900원 (다른 나라 가격은 자동 환산)

## 6단계 — 비공개 테스트 (12명 × 14일)

1. 콘솔 → **테스트 및 출시 → 테스트 → 비공개 테스트** → 트랙(기본 "Closed testing - Alpha") 관리
2. **테스터** 탭: "이메일 목록 만들기" → 테스터들의 **구글 계정(Gmail) 주소**를 넣거나, 구글 그룹 주소 하나를 등록 (그룹이 관리하기 편합니다)
3. **국가/지역**: 대한민국
4. **새 버전 만들기** → 4단계의 `.aab` 업로드 → 출시 노트(`listing.md`) → **검토 → 비공개 테스트로 출시**
   - 처음 올리면 Play 앱 서명 안내가 나옵니다 → **기본값(Google 이 앱 서명 키 관리)** 그대로 진행
5. 첫 검토(몇 시간~며칠)가 끝나면 테스터 탭의 **"웹에서 참여" 링크**를 테스터에게 보냅니다 (`testers.md` 문구)
6. 테스터는 링크에서 **"테스터 되기" → 플레이스토어에서 설치**까지 해야 인원에 들어갑니다.

**테스트를 확실히 통과하는 요령**
- 12명 딱 맞추지 말고 **15~20명** 모으세요. 중간에 빠지는 사람이 생깁니다.
- **14일 동안 계속 테스터로 남아 있어야** 합니다 (앱을 지우거나 탈퇴하지 않도록 부탁).
- 테스트 기간에 **1~2번 업데이트**를 올리세요(오타 수정이라도). 구글은 "실제로 테스트하고 개선했는지"를 봅니다.
- 테스터에게 **실제로 명함을 찍어 보고 의견을 달라고** 하세요. 7단계 설문에 그 내용을 씁니다.
- 대시보드에서 "12명 · 14일" 진행 상황이 보입니다.

## 7단계 — 프로덕션 액세스 신청

14일이 지나면 대시보드에 **"프로덕션 액세스 권한 신청"** 이 열립니다. 테스트 방법·받은 피드백·고친 점·출시 준비 상태를 묻는 설문입니다. **답변 예시는 `testers.md` 맨 아래**에 있습니다. 구체적일수록 잘 통과합니다. 심사는 보통 7일 안팎.

## 8단계 — 프로덕션 출시

1. 테스트 및 출시 → **프로덕션** → 국가: 대한민국(+원하는 나라) → **새 버전 만들기** → 최신 `.aab` → 검토 → 출시
2. 심사 후 플레이스토어에 공개됩니다.

- 거절 메일이 오면 **사유를 그대로 고쳐서 재제출**하거나 콘솔의 정책 상태 페이지에서 이의 제기. **새 계정을 만들어 다시 올리는 것은 계정 영구 정지 사유**입니다.
- 콘솔·구글 계정의 연락처를 최신으로 유지 (정책 안내 메일을 놓치면 앱이 내려갈 수 있음)

## 업데이트 올리는 법 (출시 후)

1. 코드를 고쳐 push → "명함스캔 플레이스토어 AAB" 가 자동 빌드 (버전 코드는 자동으로 커집니다)
2. 버전 이름을 올리려면 `cardscan/app.json` 의 `"version"` (예: 1.0.1)
3. 콘솔 → 프로덕션 → 새 버전 만들기 → 새 `.aab` 업로드 → 출시 노트 → 검토 (업데이트 심사는 보통 하루 안팎)
