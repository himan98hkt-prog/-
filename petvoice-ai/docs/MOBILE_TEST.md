# 실기기에서 테스트하기

우리 개 짖는 소리를 실제로 넣어 보려면 폰에 앱을 설치해야 합니다.
가장 빠른 길은 **EAS 로 APK 를 하나 만들어 안드로이드 폰에 설치**하는 것입니다.

> iOS 는 애플 개발자 계정(연 $99)이 있어야 실기기 설치가 됩니다.
> 계정이 없다면 안드로이드로 확인하세요 — 분석 결과는 플랫폼과 무관합니다.

---

## 왜 Expo Go 로는 안 되나

Expo Go 에는 이 앱이 쓰는 네이티브 모듈(결제, 보안 저장소, SQLite, 알림)이 들어 있지 않습니다.
화면은 뜨지만 녹음·저장·분석이 제대로 돌지 않습니다. **개발 빌드나 APK 가 필요합니다.**

## 왜 웹 미리보기로는 안 되나

브라우저에는 파일 시스템 접근과 보안 저장소가 없어 녹음 → base64 → 분석 경로가 끊깁니다.
화면 확인용으로는 쓸 수 있지만 정확도 테스트에는 못 씁니다.

---

## 1단계 — Gemini 키 발급 (5분)

[Google AI Studio](https://aistudio.google.com/apikey) 에서 API 키를 만듭니다. 무료 등급으로 충분합니다.

## 2단계 — APK 빌드 (15분, 대부분 대기)

```bash
npm install -g eas-cli
cd petvoice-ai
eas login                      # Expo 계정 (무료)
eas build:configure            # 처음 한 번만
eas build --profile test --platform android
```

빌드가 끝나면 터미널에 QR 코드와 다운로드 링크가 나옵니다.
**폰으로 QR 을 찍어 APK 를 받아 설치하세요.** (설정에서 "출처를 알 수 없는 앱" 허용이 필요할 수 있습니다)

> `test` 프로필은 `EXPO_PUBLIC_ALLOW_DIRECT_KEY=1` 로 빌드합니다.
> 이 플래그가 켜진 빌드에서만 아래 3단계의 키 입력 화면이 나타납니다.
> `production` 프로필은 이 플래그를 `0` 으로 두므로 **스토어에 올라가는 빌드에는 그 화면이 없습니다.**

## 3단계 — 키 넣기 (1분)

앱을 열고 `설정` 탭 → 맨 아래 **테스트 모드 (개발자용)** 카드에 키를 붙여 넣고 저장합니다.

키는 기기의 보안 저장소(Android Keystore)에만 들어갑니다. 앱 번들에도, 서버에도 올라가지 않습니다.

> ⚠️ **이건 제품 구조가 아닙니다.** 출시 앱은 키를 Supabase Edge Function 에만 두고
> 앱은 사용자 토큰만 들고 다닙니다. 이 경로는 "정확도를 직접 확인해 보고 싶다"를
> Supabase 설정 없이 하기 위한 지름길이고, 그래서 빌드 플래그로 가둬 뒀습니다.
>
> 서버까지 제대로 세우고 싶다면 [README 의 서버 배포](../README.md) 절차를 따르세요.
> 그 경우 `.env` 에 Supabase 값을 넣으면 테스트 모드 카드는 자동으로 사라집니다.

## 4단계 — 실제로 테스트하기

### 먼저 대조군부터

정확도를 재기 전에 **모델이 지어내는지**를 먼저 봅니다. 이게 더 중요합니다.

1. 아무 소리도 없는 조용한 방에서 3초 녹음 → 분석
2. TV 나 라디오 소리에 대고 3초 녹음 → 분석
3. 본인이 말하면서 3초 녹음 → 분석

**여기서 "지금 신나 보여요 (75%)" 같은 답이 나온다면,** 진짜 짖는 소리에 대한 답도
같은 방식으로 지어낸 것일 수 있습니다. 이건 정답 데이터 없이 바로 알 수 있는 신호입니다.

> 참고: 앱에는 무음·배경소음 사전 필터가 있어서 1·2번은 분석 전에 막힐 수 있습니다.
> 그게 정상 동작입니다. 필터를 통과한 소리만 모델에 갑니다.

### 그다음 같은 소리를 반복

같은 상황에서 3번 연속 녹음해 봅니다. **답이 매번 다르면** 정확도를 논할 수 없습니다.
`정밀 분석 (3회 연속)` 버튼이 이걸 자동으로 해 주지만, 종합 전 개별 결과를 보려면
그냥 3번 따로 녹음하는 편이 낫습니다.

### 마지막으로 상황을 알고 녹음

상황을 아는 채로 녹음하고, **상황 칩을 고르지 말고** 분석해 보세요.
(칩을 고르면 모델에게 정답을 알려 주는 셈이라 정확도를 잴 수 없습니다.)

- 외출 준비할 때
- 택배 기사가 왔을 때
- 밥 주기 직전
- 산책 나가기 직전

맞히는지 세어 보세요. **본인이 소리만 듣고 맞히는 비율과 비교하는 것이 핵심입니다.**
앱이 보호자 본인보다 못 맞히면, 그 기능은 아직 가치를 더하지 못하는 것입니다.

## 결과를 어떻게 볼 것인가

기대치를 미리 맞춰 두는 편이 좋습니다.

- 짖음에 맥락 정보는 실제로 있습니다 — 6,000개 짖음으로 학습한 분류기가 상황 43% (우연 17%)
- 다만 범용 멀티모달 모델은 통제된 강아지 감정 데이터셋에서 **우연 수준까지 떨어졌습니다**
- 그러니 **각성도(흥분했나)와 대략적인 긍정/부정**은 맞을 가능성이 있지만,
  "배고파" 와 "심심해" 를 가르는 것은 기대하지 않는 편이 맞습니다

자세한 배경과 지표 정의는 [`eval/README.md`](../eval/README.md) 에 있습니다.
클립을 파일로 모아 두면 같은 검사를 자동으로 돌릴 수 있습니다.

```bash
npm run eval:controls
npm run eval -- --provider gemini --repeat 3
```

## 문제가 생기면

| 증상                                  | 원인                                                                                |
| ------------------------------------- | ----------------------------------------------------------------------------------- |
| 설정에 테스트 모드 카드가 없다        | `test` 프로필로 빌드하지 않았거나, `.env` 에 Supabase 값이 들어 있다                |
| 분석하면 항상 같은 답이 나온다        | 키를 안 넣어 데모 응답으로 돌고 있다 (앱 정보의 "분석 서버"가 `데모 모드`인지 확인) |
| 녹음 버튼을 눌러도 반응이 없다        | 마이크 권한 거부 — 설정 앱에서 허용                                                 |
| "소리가 거의 들리지 않았어요" 만 뜬다 | 사전 필터가 막는 것. 더 가까이서, 실제로 짖을 때 녹음                               |
| 분석 실패가 계속 난다                 | 키가 잘못됐거나 무료 할당량 초과. AI Studio 에서 확인                               |
