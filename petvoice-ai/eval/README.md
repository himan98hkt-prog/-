# 분석이 실제로 맞는가 — 검증 방법

이 폴더는 **PetVoice AI 의 해석이 정확한지 재기 위한 도구**입니다.
앱 코드가 아니라 개발 도구이고, 배포 번들에 포함되지 않습니다.

---

## 먼저, 지금까지 검증된 것과 안 된 것

| | 상태 |
|---|---|
| 모델 응답을 앱이 안 깨지고 처리하는가 | ✅ 테스트 196건 |
| 감정 점수 합이 100이 되는가 | ✅ |
| 이상 징후 규칙이 의도대로 작동하는가 | ✅ (규칙이 규칙대로 도는지) |
| **그 해석이 실제 개의 상태와 맞는가** | ❌ **한 번도 검증되지 않았습니다** |

기존 테스트는 전부 **계약(contract)** 검사입니다. 모델이 "playful 75%" 라고 하면
앱이 그걸 제대로 표시하는지를 봅니다. 그 75% 가 맞는 숫자인지는 아무도 확인하지 않았습니다.

이상 징후 판정의 임계값(`PAIN_VET_THRESHOLD = 20`, `ANXIETY_WATCH_THRESHOLD = 45`)도
데이터에서 나온 값이 아니라 **설계 시점에 정한 값**입니다. 근거 있는 숫자로 바꾸려면 측정이 필요합니다.

## 문헌이 말하는 것: 어디까지 가능한가

### 가능한 쪽

짖는 소리에는 **맥락 정보가 실제로 담겨 있습니다.**
6,000개가 넘는 짖음을 6가지 상황에서 녹음해 기계학습으로 분류한 연구에서,
상황 분류 **43%**, 개체 식별 **52%** 를 얻었습니다
([Molnár et al., *Animal Cognition* 2008](https://link.springer.com/article/10.1007/s10071-007-0129-9)).
우연 수준이 약 17% 이므로 **정보는 분명히 있습니다.**

특히 신뢰할 만한 축은 두 가지입니다.
- **각성도** — 얼마나 흥분했는가 (짖음 간격, 음높이)
- **정서가** — 대략 긍정인가 부정인가 (음높이가 높고 맑을수록 놀이·인사, 낮고 거칠수록 위협·경계)

### 어려운 쪽

같은 연구에서 상황 분류가 **43% 에 그쳤다**는 점이 중요합니다.
사람이 들어도, 기계가 들어도 절반은 틀립니다. "지금 배고파" 와 "지금 심심해" 를
소리만으로 갈라내는 것은 현재 기술로도 안정적이지 않습니다.

### 우리가 쓰는 방식의 특수한 위험

우리는 짖음 전용으로 학습된 모델이 아니라 **범용 멀티모달 모델(Gemini)** 을 씁니다.
이 접근을 직접 검증한 최근 연구가 있습니다
([Scientific Reports, 2025](https://www.nature.com/articles/s41598-025-25199-7)).

> 범용 비전-언어 모델(GPT-4o·Gemini·LLaVA 등)은 웹에서 모은 강아지 감정 사진에서는
> 그럴듯한 정확도를 냈지만, **배경과 견종 생김새 같은 표면적 단서**에 기대고 있었다.
> 배경을 없애고 감정을 실험적으로 유도한 통제 데이터셋에서는 **우연 수준까지 떨어졌다.**

우리 앱의 사진 분석 경로가 정확히 이 구조입니다.
그럴듯한 답이 나온다고 해서 실제로 감정을 읽고 있다는 뜻이 아닙니다.

## 그래서 무엇을 어떻게 재는가

정확도를 "말풍선 문장이 맞았는가" 로 재면 안 됩니다. 그건 애초에 정답이 없습니다.
대신 네 가지를 순서대로 잽니다. **앞의 둘은 라벨 없이 오늘 당장 잴 수 있습니다.**

### 1. 자기 일관성 — 라벨 불필요

같은 클립을 3번 넣으면 같은 답이 나오는가.

여기서 낮으면 정확도를 논하는 것 자체가 무의미합니다. 매번 다른 말을 한다는 뜻이니까요.
**가장 먼저, 가장 싸게 할 수 있는 검사입니다.**

```bash
npx vite-node eval/run.ts -- --provider gemini --repeat 3
```

### 2. 대조군 반응 — 라벨 불필요

무음, 에어컨 소음, 기계음, 사람 말소리 리듬, 손뼉 소리를 넣습니다.
정답이 없는 입력입니다.

> 무음에 대고 "지금 신나 보여요 (75%)" 라고 답한다면,
> 진짜 짖는 소리에 대한 답도 같은 방식으로 지어낸 것일 수 있습니다.

이건 정확도를 재는 게 아니라 **모델이 지어내는 성향이 있는지**를 재는 것이고,
그래서 정답 데이터 없이도 강력합니다.

```bash
node eval/make-controls.mjs      # 대조군 오디오 생성
```

### 3. 상황 분류 정확도 — 라벨 필요

보호자가 상황을 알고 녹음한 클립을 모읍니다.
"외출 직전", "택배 기사 방문", "밥 주기 전" 처럼요.

- 필요량: 상황당 최소 30개, 개체 10마리 이상 (한 마리에 과적합되지 않게)
- 비교 기준 셋:
  - **우연 수준** (상황 6개면 17%)
  - **문헌 수준** (43%) — 이걸 못 넘으면 범용 모델을 쓸 이유가 없습니다
  - **보호자 본인의 추측** — 이걸 못 넘으면 앱이 더해 주는 게 없습니다

세 번째가 가장 중요합니다. 보호자는 자기 개를 잘 압니다.

### 4. 이상 징후 플래그 — 수의사 확인 필요

**이 앱에서 정확도가 실제로 중요한 유일한 지점입니다.**
말풍선이 틀리면 재미가 없을 뿐이지만, 통증 신호를 놓치면 아픈 개를 놓칩니다.
반대로 헛다리를 자주 짚으면 사용자가 진짜 경고를 무시하게 됩니다.

- **민감도** — 실제로 문제가 있던 아이 중 몇 %를 잡아냈는가
- **특이도** — 멀쩡한 아이 중 몇 %를 그냥 지나갔는가

정확도 하나만 보면 안 됩니다. 아픈 개는 드물어서 "전부 괜찮다"고만 답해도 정확도는 높습니다.

## 데이터셋 만들기

`dataset/manifest.json` 형식은 `manifest.example.json` 을 보세요.

```jsonc
{
  "file": "real/choco-alone-01.wav",
  "contextTag": "separation",              // 보호자가 아는 실제 상황
  "pet": { "name": "초코", "type": "DOG", "breed": "포메라니안", "ageMonths": 18 },
  "actuallySick": false                    // 수의사 확인이 있으면
}
```

라벨링 원칙:
- **소리를 듣고 라벨하지 마세요.** 상황을 보고 라벨해야 합니다. 소리를 듣고 정하면 사람의 편향이 정답에 섞입니다.
- 한 마리에서 너무 많이 모으지 마세요. 개체 식별이 52% 라는 건, 모델이 상황이 아니라 **그 개를** 외울 수 있다는 뜻입니다.
- 대조군을 반드시 섞으세요.

## 결과를 어디에 반영할 것인가

측정 결과에 따라 제품이 바뀌어야 합니다.

| 측정 결과 | 제품에 해야 할 일 |
|---|---|
| 자기 일관성이 낮다 | 온도를 낮추고 정밀 분석(3회 종합)을 기본값으로 |
| 대조군에 확신한다 | 프롬프트에 "판단 불가" 선택지를 강화하고, 사전 필터를 더 엄격하게 |
| 상황 분류가 우연 수준이다 | **감정 확률 퍼센트 표시를 걷어내야 합니다.** 측정되지 않은 정밀도를 보여 주는 셈입니다 |
| 이상 징후 민감도가 낮다 | 임계값을 낮추거나, 기능 자체를 재검토 |
| 이상 징후 특이도가 낮다 | 임계값을 올려야 합니다. 양치기 소년이 되면 진짜 경고도 무시당합니다 |
