# 주문 안전성 강화 베타 — 실전 승인 아님

기준: PR #7의 `fb3631b1dd2103ae5a022ce20b886e5345c0fe3a`.
개선 브랜치: `codex/trading-safety-hardening`.

## 이번 버전에 구현한 것

- 주문 접수 직후 KIS 주문번호를 DB에 저장하고 이후에 체결을 조회합니다.
- 체결 0주를 요청수량 전체로 바꾸지 않습니다. 부분체결은 확인된 수량만 반영합니다.
- 명시적인 증권사 업무 거부만 REJECTED로 처리합니다. 타임아웃·HTTP 오류·응답 파싱 실패는 AMBIGUOUS로 남겨 재주문을 막습니다.
- SUBMITTING/PENDING/PARTIAL/UNKNOWN/AMBIGUOUS/CANCEL_PENDING 중 하나라도 남으면 계좌 전체 신규 주문을 차단합니다. 이 차단에는 손절 매도도 포함됩니다. 즉시 증권사 앱에서 확인해야 합니다.
- 미확정 주문이 있는 상태에서 다른 실행 경로가 주문 기록을 생성하는 경쟁을 SQLite BEGIN IMMEDIATE로 차단합니다. 다른 폴더/다른 PC의 별도 DB까지 중복 실행을 막지는 못합니다.
- 과거 날짜 주문도 원래 주문일로 재조회합니다. PARTIAL 상태가 유지돼도 누적 체결수량을 갱신합니다.
- 취소 API 응답만으로 취소 완료라 하지 않습니다. 재조회 전까지 CANCEL_PENDING이며, 취소와 체결이 경합하면 최종 확인 수량을 반영합니다.
- 주문번호·종목·수량·체결가가 불일치하거나 비정상인 체결 응답은 확정하지 않습니다.
- 비 DRY_RUN 매수 직전 전용 주문가능현금 조회와 리스크 검사를 다시 합니다. 지정가가 현재가보다 높으면 그 가격 기준으로 수량을 줄입니다.
- STOP은 주문 전송 직전에도 다시 확인합니다. 이미 전송 중이거나 접수된 주문은 소급 취소되지 않습니다.
- DB는 최초 사용 계좌/환경의 해시에 연결됩니다. 다른 계좌 또는 VTS/REAL 전환 시 같은 DB 사용을 거부합니다.
- 비 DRY_RUN 손익은 KIS 순자산으로 계산하며 유효한 순자산이 없으면 중단합니다. 일일 손실 한도 도달 이력은 DB에 남겨 반등·재시작 후에도 당일 매수를 잠급니다. 실제 손익 수치는 잠금 때문에 바꾸지 않습니다.
- 자동매매 실행기의 REAL 주문은 LIVE_TRADING_ENABLED=false 기본값으로 별도 잠깁니다. 환경 전환 시 DRY_RUN=true, 화면 설정 저장 시 실전 잠금으로 돌아갑니다. 실행 중 환경 전환은 거부합니다.
- 실전 주문에는 해당 연도 휴장일 목록이 필요합니다. 목록의 완전성·특별 개장시간까지 자동 검증하지는 않습니다.
- 업데이트 ZIP을 커밋 SHA로 고정하고 경로 이탈·심볼릭 링크를 거부합니다. config/loader.py도 업데이트하며, 예외 발생 시 코드 백업 복구를 시도합니다. 복구 실패 시 백업 위치를 알리고 자동 재시작하지 않습니다.
- 의존성 변경 시 자동 pip 설치와 봇 재개 대신 수동 재시작을 요구합니다. constraints.txt는 검증 환경 버전을 고정합니다.

## 안전하게 설치하기

1. 기존 프로그램을 종료합니다. 증권사 앱에서 보유·미체결을 확인합니다. 정지 버튼은 주문 취소나 보유 종목 청산 버튼이 아닙니다.
2. **기존 설치 폴더 전체를 보존**하고 새 브랜치 ZIP을 다른 폴더에 풉니다. 실행 파일은 ZIP 안의 auto_trader 폴더에 있습니다.
3. Python 3.12를 권장합니다. Windows는 start.bat, macOS/Linux는 start.sh로 실행합니다. 이 변경은 Linux/Python 3.12에서 오프라인 검증했으며 Windows 설치는 별도 확인이 필요합니다.
4. 새 설치에서 모의계좌 키를 설정하고 KIS_ENV=VTS, DRY_RUN=true, LIVE_TRADING_ENABLED=false를 유지합니다. 비밀키를 GitHub·채팅에 올리지 마세요.
5. VTS 주문을 실제 모의계좌로 보내는 단계는 별도 승인·확인 후 진행합니다. scripts/test_kis.py는 조회 전용이 아니라 주문을 발생시키는 시험입니다. 이번 개발 과정에서는 실행하지 않았습니다.
6. 기존 data/ DB를 무심코 덮어쓰거나 삭제하지 마세요. 계좌 정보 없는 옛 DB에 실주문 기록이 있으면 안전을 위해 사용을 거부합니다. 이전 DB는 감사 자료로 보존하고 새 DB/전용 모의계좌에서 시작하세요. 기존 보유는 KIS 잔고 동기화 시 다시 읽습니다.

## 미확정 주문이 발견되면

- 자동주문이 차단되는 것은 의도된 동작입니다. 프로세스를 재시작하거나 STOP을 해제해도 DB의 미확정 주문 차단은 해제되지 않습니다.
- 주문번호가 있으면 정규 사이클/손절 감시의 재조회로 확정합니다. 조회 오류나 자료 불일치가 있으면 차단을 유지합니다.
- 주문번호 없는 AMBIGUOUS/SUBMITTING은 이 버전에서 자동으로 종목·시간을 추측해 연결하지 않습니다. 증권사 주문·체결 원장과 로그를 대조한 별도 복구 작업이 필요합니다. 임의로 DB 행을 삭제하거나 REJECTED로 바꾸지 마세요.
- 기존 프로그램에서 누락된 주문번호·과거 REJECTED 오분류를 이 버전이 자동 복원하지 않습니다.

## 아직 구현·검증이 필요한 것

이 버전은 **주문 무결성 중심 1차 개선**이며 앞선 분석의 모든 과제를 완료한 버전이 아닙니다.

- 실제 KIS 응답과 순자산·주문가능금액 필드, 거래일·TR ID·주문 취소의 최신 계약 검증. 이번 시도에서 공식 샘플 페이지 접근이 차단되어 최신 계약 대조를 완료하지 못했습니다.
- 비용·세금·슬리피지 및 과최적화 방지를 포함한 백테스트/워크포워드, 벤치마크 비교와 실제 수익률 검증. LLM에 과거 날짜를 주는 것만으로 미래 정보 누출 없는 백테스트가 되지 않습니다.
- 새 모의계좌 5일 연동 검증 후 장기 모의 운영. 거래 횟수가 적으면 기간을 늘립니다. 5일 수익이나 테스트 통과 수는 수익성 증명이 아닙니다.
- 휴장일 자동 동기화와 특별 개장시간, 시장별 호가단위 검증. 현재 휴장일 파일은 예시뿐입니다. 지정가 호가단위는 아직 보완 대상입니다.
- 주문 상태의 수동 복구 UI, 증권사 원장 기준 미체결 일괄 취소, 서로 다른 프로세스/PC의 계좌 단일 실행.
- 입출금/배당/기업행동 조정 수익률, 전일 기준 평가 및 장중 시작일의 기준자산 처리. 현재 당일 최초 동기화 대비 계좌 순자산 변화입니다. 입출금이 있으면 전략 손익으로 해석하면 안 됩니다.
- 전원 차단 중 업데이트의 완전한 원자성. 현재는 잡힌 예외의 롤백이며 OS 크래시까지 보장하지 않습니다. 기존 보호 설정은 .new 파일과 비교해야 합니다.
- AI 지연 중 독립 손절 감시, 데이터 신선도·결측 지표 처리, 실전 주문가격 슬리피지 상한. 일반 사이클과 손절 감시는 같은 락을 사용하므로 손절 주기가 보장되지 않습니다.

실전 잠금을 해제하거나 자금을 확대할 근거가 아직 없습니다. AI 모델 수 추가, 승률·수익률 보장, 투자 전략 변경은 이번 개선에 포함되지 않습니다.

## 검증 명령 — 외부 API 미사용

```bash
python -m pip install --use-pep517 -r requirements.txt
python -m pip check
python -m pytest -o addopts='' -q
```

정상 기대값을 안전 계약에 맞춰 변경한 기존 테스트도 포함합니다. 테스트를 삭제하거나 실패를 무시하지 않습니다.

이 결과는 실제 증권사 API·Windows 설치·시장 수익률 검증을 포함하지 않습니다.
