02

인증키로 여는 제품

첫 실행에서 인증 화면이 뜹니다. 구매한 키를 넣거나 14일 체험을 시작해야 앱으로 들어갑니다. 체험이 끝나도 자료는 그대로 남고, 키를 넣으면 하던 작업을 이어서 씁니다.

AP7W–DZYP–1TY7C
A제품 — A는 피아노 관리노트와 공용인 통합키. M은 학원 전용, K는 피아노 전용.
P플랜 — L은 Lite(기기 1대·완전 오프라인), P는 Pro(여러 기기 실시간 동기화).
6자랜덤 — 받아 적을 때 헷갈리는 I·L·O·U는 쓰지 않습니다.
4자검증번호 — 한 글자만 틀려도 앱이 거부하고 이유를 알려 줍니다.

피아노 관리노트와 키를 함께 쓰는 방법

두 제품이 같은 발급 규칙을 쓰면 됩니다. 이 저장소의 src/core/license.js를 피아노 앱에 그대로 넣고 PRODUCT_CODE만 'K'로 바꾸면, 통합키(A)는 양쪽에서 열리고 전용키는 각자 제품에서만 열립니다. 잘못된 키를 넣으면 “피아노 관리노트 전용 키입니다”처럼 이유가 표시됩니다.

전제 하나를 밝혀 둡니다. 피아노 관리노트의 소스를 받지 못해, 그쪽 앱을 직접 수정하지는 못했습니다. 지금 상태는 “같은 모듈을 넣으면 즉시 공용이 되는” 구조까지 만들어 둔 것입니다. 피아노 쪽 license.js(또는 키 발급 코드)를 주시면 제가 맞춰 넣겠습니다.

라이선스가 사라지지 않는 자리

  • 인증 정보는 기기의 것으로 취급합니다. 데모 데이터 넣기·초기화·백업 복원에도 인증이 유지됩니다.
  • 반대로 백업 파일에는 인증키가 담기지 않습니다. 백업을 복사해 다른 기기에서 라이선스를 복제할 수 없습니다.
  • 기기마다 6자리 기기번호가 표시되어 재발급·문의 대응에 씁니다.
  • 제품 구분이 없던 초기 발급분(첫 자리 L/P)도 계속 인정합니다. 회수할 필요가 없습니다.
03

원장의 반복 업무를 어디까지 줄였나

학원 현장에서 시간을 가장 많이 먹는 일은 “기록”이 아니라 확인·안내·계산·정리입니다. 기존 앱은 기록은 잘 받아 주지만 나머지를 원장에게 남겨 두고 있었습니다. 그 일곱 가지를 화면 안으로 옮겼습니다.

매일·매달 하던 일지금상태
오늘 뭘 해야 하는지 머릿속으로 점검 오늘 탭 — 출결 미체크 반, 결석 안내 대상, 미납 독촉, 방치된 후속 상담, 백업 경과를 한 화면에. 각 줄에 처리 버튼이 붙습니다. 신규
결석한 학생 학부모에게 한 명씩 문자 일괄 안내 — 대상 선택 → 이름·금액이 각자 값으로 채워진 문구 생성 → 전체 복사 / 번호만 복사 / CSV / 문자앱 열기. 누구에게 보냈는지 이력이 남습니다. 신규
미납자 뽑아 개별 독촉 수납 탭 미납자 일괄 안내. 납부 기준일이 지나야 독촉 대상이 되고, 연체 일수가 표에 표시됩니다. 신규
형제 할인·개인 할인 계산기로 두드리기 설정에 규칙을 한 번 정하면 청구 생성이 자동 계산합니다. 미리보기로 “누가 얼마”를 먼저 보고 만들고, 할인 내역이 청구서와 영수증에 그대로 남습니다. 신규
엑셀 명단을 손으로 옮겨 적기 엑셀 가져오기 — 표를 그대로 붙여넣거나 CSV 업로드. 열 이름 자동 인식, 이미 등록된 원생 표시, 없는 반 자동 생성. 신규

지금 바로 확인하는 법

  • 체험판 파일 하나 — 학원관리노트-체험판.html을 더블클릭. 인증 화면에서 “14일 무료 체험 시작”을 누르면 바로 씁니다.
  • 정식 배포본 — lite.html(단일 기기) / index.html(Pro)은 웹호스팅에 올리거나 npx serve .로 확인합니다. 더블클릭으로는 열리지 않습니다(브라우저 보안 정책).
  • 인증키 발급 — tools/keygen.html. 판매자 전용이므로 고객 서버에 올리지 마세요.
