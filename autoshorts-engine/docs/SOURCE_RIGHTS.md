# 원본 영상 권리 확인 — 지점 정리 (Phase 0 초안)

Phase 0 은 **어디에서 권리를 물어야 하는지**만 정리한다. 판정 로직과 UI 는 뒤 Phase 의 일이다
(저장 필드는 Phase 2, 확인 흐름과 라이선스 근거 보관은 Phase 7, 발행 승인 게이트는 Phase 8).

## 전제

이 제품은 **남이 만든 롱폼 영상을 잘라** 쇼츠를 만든다. 그래서 권리 문제는 부가 기능이
아니라 제품의 핵심 위험이다. 두 가지를 분리해서 본다.

1. **원본을 가져올 권리** — 다운로드/처리해도 되는가
2. **결과물을 발행할 권리** — 잘라 만든 쇼츠를 올려도 되는가

1이 된다고 2가 되는 것은 아니다.

## 현재 코드가 가정하는 것 (그리고 그게 왜 위험한가)

| 위치 | 지금 동작 | 문제 |
|---|---|---|
| `downloader.py` | URL 을 받으면 곧바로 내려받는다 | 권리 확인 단계가 없다 |
| `trend_finder.py` | 급상승 영상을 찾아 "원클릭 제작"으로 연결 | **남의 인기 영상을 그대로 자르도록 유도**한다 |
| `uploader.py` | 기본 `private`, `public` 은 경고 1회 | 경고는 기록되지 않고, 확인했다는 증거도 없다 |
| 전체 | 권리 상태를 저장하는 필드가 없다 | 나중에 "확인했었나?"를 답할 수 없다 |

`trend_finder` → 제작 → 업로드가 한 줄로 이어지는 흐름이 가장 위험하다. 지금은
사람이 중간에서 판단할 자리가 강제되지 않는다.

## 권리를 물어야 하는 지점

```
[탐색/입력]  ← ① 소스 출처와 권리 상태를 받는다 (필수 입력)
     ▼
[다운로드]   ← ② unverified 면 진행 여부를 사람이 정한다
     ▼
[분석/렌더]  ← (권리와 무관. 다만 결과물에 상태를 달고 다닌다)
     ▼
[검토]       ← ③ 사람이 결과물을 보고 승인한다
     ▼
[발행]       ← ④ owned/licensed 가 아니면 public 발행을 막는다
```

### ① 입력 시점

받아야 하는 값 — `benchmark.py` 의 `RIGHTS_STATUSES` 와 같은 어휘를 쓴다.

| 값 | 뜻 | 발행 |
|---|---|---|
| `owned` | 내가 만든 영상 / 내 채널 | 허용 |
| `licensed` | 사용 허락을 받았다 (계약·서면) | 허용, 근거 보관 |
| `creative_commons` | CC 라이선스라고 표시돼 있다 | **자동 허용하지 않는다** (아래 참고) |
| `unverified` | 확인하지 않았다 | private 까지만 |

기본값은 `unverified` 다. 사용자가 고르지 않으면 안전한 쪽으로 둔다.

### ② 다운로드 시점

- `unverified` 인 소스도 **처리 자체는 막지 않는다** (개인 검토·실험 용도가 있다).
- 다만 그 사실을 job 에 기록하고, 산출물에 `unverified` 표시를 유지한다.
- 할당량/비용을 쓰는 작업이므로, 사용자가 상태를 인지한 뒤 진행하게 한다.

### ③ 검토 시점

- 사람이 승인하지 않은 결과물은 발행 대상이 아니다 (Phase 3 의 human approval state).
- 승인 기록에 **누가/언제/어떤 권리 상태로** 승인했는지 남긴다.

### ④ 발행 시점

- `owned` / `licensed` 가 아니면 `public` / 예약 공개를 **막는다**.
- `private` 업로드는 허용한다 (사용자 본인 검토용).
- 차단 사유를 사용자가 읽을 수 있게 표시한다.

## Creative Commons 를 "안전"으로 읽지 않는다

`CLAUDE_CODE_MASTER_V3.md` Phase 7 의 지시를 그대로 따른다.

- CC 표시는 **업로더의 주장**이다. 업로더가 그 권리를 실제로 가졌는지는 별개다.
- 영상 안의 음악·클립·폰트·상표는 CC 범위 밖일 수 있다.
- CC-BY 는 **출처 표시 의무**가 있다. 자동 발행에서 이 의무를 빠뜨리면 위반이다.

그래서 `creative_commons` 는 `owned`/`licensed` 와 같은 급으로 취급하지 않고,
아래를 함께 저장해야 발행 후보가 된다 (Phase 7 에서 구현).

| 필드 | 뜻 |
|---|---|
| `license_id` | 어떤 라이선스인가 (예: CC-BY-3.0) |
| `license_evidence` | 근거 (스크린샷/응답 원문/문서 링크) |
| `checked_at` | 확인 시각 |
| `source_url` | 원본 주소 |
| `attribution_text` | 발행물에 넣을 출처 표기 |
| `checked_by` | 확인한 사람 |

## YouTube 쪽 제약 (별개로 존재)

Google 공식 `videos.insert` 문서 기준으로, 2020-07-28 이후 만든 **미검증 API 프로젝트**의
업로드는 private 으로 제한될 수 있고 해제에는 API compliance audit 이 필요하다.
즉 권리 문제를 해결해도 **API 심사가 끝나기 전에는 공개 발행을 상품 약속으로 쓸 수 없다.**
자세한 순서는 `docs/PRIVATE_UPLOAD_SMOKE.md` 의 "공개 발행 전 조건" 참고.
