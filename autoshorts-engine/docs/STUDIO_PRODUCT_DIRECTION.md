# Shorts Studio 상품 구조

## 제품 경계

하나의 계정·워크스페이스·프로젝트 안에 서로 다른 제작 모드를 둔다.
분석 모드: 사용자가 이용 권리를 가진 영상에서 음성인식, 구간 선정, 자막, 세로 렌더.
제작 모드: 주제에서 기획, 대본, 음성, 미디어, 렌더를 생성하는 shorts-factory.
기존 두 엔진을 같은 것으로 취급하거나 기존 운영 저장소를 덮어쓰지 않는다.

## 현재 구현

- 공통 UI, 계정, 프로젝트, 분석 작업 이력과 결과 다운로드.
- 프로젝트별 factory-plan 스냅샷 저장·복원·내보내기. 기존 revision 저장소 재사용.
- factory-jobs는 409로 거부하며 큐·외부 API·비용 장부를 변경하지 않는다.
- 분석 서비스의 유료 AI 기본 차단. 환경변수에 키만 존재해서는 유료 호출이 발생하지 않는다.
- 기존 shorts-factory 배포·예약·키는 독립적으로 유지한다.

## 제작 엔진 통합에서 이어갈 계약

shorts-factory는 별도 워커/컨테이너에서 실행한다. 두 엔진의 의존성과 전역 경로가
충돌하지 않게 하며, 워크스페이스별 작업 디렉터리를 주입한다. API에서는 인증과
입력 검증, 비용 예약, 큐 등록만 처리한다. 제조 엔진 소스는 비공개 자산이므로
현재 공개 분석 저장소에 복사하지 않는다.

생성 재개 전 필수 구현: 기획→factory Script 변환, 공통 작업 식별자·단계 이벤트,
결과 저장소 등록, 취소·재시도 시 기존 산출물 재사용, 워크스페이스별 API 키 격리,
공급자 비용 상한·호출 전 예약·실사용 정산·상한 도달 차단.
어떤 제작 모드도 렌더 완료만으로 외부 플랫폼에 게시하지 않는다.
게시 기능은 별도 권한·사용자 확인·예약 상태·OAuth 계정 연결을 가진다.

## 사업화 게이트

먼저 분석 모드를 소규모 사용자 테스트에 제공해 한국어 정확도·선정 구간 만족도·
평균 처리 시간·완료율을 기록한다. 공개 서비스 전에는 배포용 인증·접근 경계,
비밀정보 관리, 백업·복구, 업로드/작업 자원 제한, 취소 강제 종료를 검증한다.
유료 제작은 비용 상한을 실제로 강제할 수 있는 다음 릴리스에서 연결한다.
이 문서는 출시 완료나 매출 보장을 의미하지 않는다.
