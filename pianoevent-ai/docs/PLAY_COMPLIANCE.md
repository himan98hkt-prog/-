# Google Play 정책 · 보안 컴플라이언스 대응 현황

개발 지시서의 체크리스트를 항목별로 어디에서 어떻게 지켰는지 정리합니다.
(웹 서비스 기준으로 구현했고, 모바일 앱 패키징 시 필요한 잔여 작업을 함께 적었습니다.)

## 1. AI API Key 은닉 — 완료

| 요구 | 구현 |
|---|---|
| 클라이언트에 `GEMINI_API_KEY` 노출 금지 | 키는 `lib/ai/gemini.ts` 안에서만 읽고, 이 모듈은 브라우저에서 import 되면 **즉시 예외를 던집니다**. `next.config.mjs` 에서 `@google/genai` 를 서버 외부 패키지로 지정해 클라이언트 번들에 섞이지 않게 했습니다. |
| 프록시 구조 | 웹은 `app/api/*` 서버 라우트가 키를 들고 호출합니다. 모바일 앱용으로는 `supabase/functions/gemini-proxy/index.ts` 를 제공합니다 — **Authorization 헤더 검증 → 사용자 확인 → 모델 화이트리스트 → 입력 길이 제한** 후 Gemini 를 호출합니다. |
| 환경변수 실수 방지 | `.env.example` 에 `NEXT_PUBLIC_` 접두사 금지를 명시했습니다. |

## 2. 개인정보처리방침 URL — 완료

- `/privacy` 라우트로 제공합니다. 이 URL 을 Play Console 의 개인정보처리방침 주소로 등록하면 됩니다.
- 수집 항목(원장 입력 / 학부모 입력 / 자동 생성), 이용 목적, 보유 기간, **처리 위탁(Supabase · Google Gemini · Vercel)**,
  만 14세 미만 아동 조항, 이용자 권리 행사 방법, 파기 절차, 기술적·관리적 대책을 담았습니다.
- 사업자명·문의 이메일·시행일은 `NEXT_PUBLIC_OPERATOR_NAME` · `NEXT_PUBLIC_CONTACT_EMAIL` ·
  `NEXT_PUBLIC_PRIVACY_EFFECTIVE_DATE` 환경변수로 채웁니다. **배포 전 반드시 채우세요.**

## 3. 계정 및 데이터 삭제 메커니즘 — 완료

- 앱 내 경로: **설정 → 계정 및 모든 데이터 삭제** (`components/settings/delete-account.tsx`)
- "삭제" 를 정확히 입력해야 실행되며, 실행 시 학원 → 행사 → 학생 → 참석 회신이 모두 지워지고 세션 쿠키까지 폐기됩니다.
- Supabase 스키마는 `on delete cascade` 로 연쇄 삭제하며, 로그인 기반으로 전환할 때를 대비해
  `public.delete_my_account()` 함수(SECURITY DEFINER)를 제공합니다 — `auth.users` 행까지 함께 삭제합니다.
- 스모크 테스트가 삭제 후 데이터가 남지 않는지 매번 확인합니다.

## 4. 런타임 권한 요청 — 해당 없음 (웹)

현재 웹 앱은 카메라·마이크·갤러리·위치 권한을 사용하지 않습니다.
모바일로 패키징하면서 로고 업로드에 갤러리를 쓰게 되면, **권한 요청 직전에 용도 설명 다이얼로그를 먼저 띄우고**
거부 시에도 URL 입력으로 대체 가능한 경로를 남겨야 합니다.

## 6. 그 밖에 지킨 것

- 모든 사용자 입력은 서버에서 길이·형식을 검증합니다 (`lib/http.ts`).
- 학부모 참석 회신은 **쓰기만** 가능하고, 읽기는 원장만 가능하도록 RLS 정책을 분리했습니다.
- AI 에 전송하는 데이터는 학생 이름·연주곡·난이도·특징 메모로 한정하며,
  **학부모 회신 정보는 전송하지 않습니다** (개인정보처리방침 4항과 일치).
- 초대장 미리보기 iframe 에는 `sandbox` 를 적용했습니다.
