> Linux 에서는 에이전트가 **테스트 화면(움직이는 패턴)과 입력 기록 모드**로 동작합니다.
> 즉, 아래 성공 항목은 "프로토콜·보안·세션 로직이 맞다"는 뜻이며, **실제 Windows 화면 캡처와 마우스/키보드 반영은 아직 미검증**입니다.

종단간 테스트 세부 항목:
- 장치 ID 생성, 중계 서버 연결
- 최초 등록: PC 확인 요청 표시 → 승인 → 접속 / 휴대폰·PC 확인 코드 일치
- 무단 접근: 미등록 기기 거부, 없는 장치 ID 오프라인, PC 에서 거부 시 접속 불가, 등록 해제한 기기 즉시 거부
- 상태(CPU/RAM/디스크), 모니터 목록, 모니터별 캡처, 축소 전송, 실시간 전송(디버그 빌드 약 9 fps)
- 입력: 우클릭, 한글 문자열, 조합키, 휠 / 보기 전용 기기의 조작 거부
- 긴급 차단: 스트리밍 중 즉시 종료, 차단 중 접속 거부, 해제 후 재접속
- 중계 서버 재시작 후 자동 재연결, 에이전트 재시작 후 장치 ID·등록 유지, 접속 기록, 로그에 비밀키 없음

## I. AI 작업 관리 실기 (2026-10-13)

API 키 없음. Claude Code 는 PC 에 설치된 공식 CLI(`claude -p`, 사용자 구독), Ollama 는 로컬 모델.

| # | 항목 | 결과 | 비고 |
|---|---|---|---|
| 1 | 도구 찾기 | 성공 | Claude Code(npm claude.cmd), Ollama qwen3:14b·qwen2.5:7b |
| 2 | Ollama 작업 (hp-cli, 한국어) | 성공 | 실시간 출력, 완료 상태 |
| 3 | Claude Code 작업 | **로그인 필요 안내 확인** | 이 PC 의 Claude Code 가 로그인되지 않은 상태 → "PC 에서 'claude' 를 실행해 로그인" 안내로 실패 처리. 로그인된 PC 에서 실제 작업은 미검증 |
| 4 | 휴대폰 첫 AI 요청 → PC 확인창 | 성공 | 사용자가 PC 에서 [예] (기기별 기억) |
| 5 | **휴대폰에서 작업 실행 → 실시간 결과** | **성공** | Ollama qwen2.5:7b, 휴대폰 화면에 결과 표시 |
| 6 | 작업이 PC 에 남아 다른 접속에서도 보임 | 성공 | hp-cli 로 만든 작업이 휴대폰 목록에 표시 |
| 7 | 프롬프트 명령 주입 방지 | 설계 | 프롬프트는 표준 입력으로만 전달, 명령줄 인수는 고정값 |
