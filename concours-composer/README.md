# ConcoursComposer

학생 맞춤형 AI 콩쿨 독창곡 생성기. 원장이 학생의 수준·손 크기·성향·콩쿨 부문을 넣으면
**연주 가능한 독창곡**을 MusicXML 로 만든다.

**설치·구성·기능을 한 번에 보려면 [docs/OVERVIEW.md](docs/OVERVIEW.md).**

명세는 [SPEC.md](SPEC.md), 실제 구현 범위는 [docs/SCOPE.md](docs/SCOPE.md),
진행 상황과 한계는 [docs/STATUS.md](docs/STATUS.md), 작업 규칙은 [CLAUDE.md](CLAUDE.md).

## 이 프로그램의 전제

언어모델에게 "32마디 콩쿨곡 써줘" 라고 하면 문법은 맞지만 밋밋하거나 앞뒤가 따로 노는
곡이 나온다. 그래서 이 시스템은 **작곡가가 일하는 순서**를 코드로 강제한다.

```
Stage 0  스타일 컨텍스트 조립      학생 하드 제약 + 콩쿨 규정 + 참고 스타일(저작권 가드 통과분)
Stage 1  모티브 후보 3~5개    ★   원장이 고른다. 고른 모티브는 잠기고 이후 전 단계가 참조한다
Stage 2  설계(Plan)          ★   형식·마디별 화성·클라이맥스·쇼케이스. 규칙 검사 통과해야 진행
Stage 3  프레이즈 단위 실현       2~8마디씩 순차 생성. 앞 8마디를 문맥으로 받는다. 즉시 검증
Stage 4  조립                    JSON → music21 → MusicXML 3.1 (결정적)
Stage 5  채점 + 비평 루프         규칙 지표 9종 + 별도 비평가 호출 → 미달이면 해당 프레이즈만 재생성
Stage 6  후처리                  운지·해설·모의 심사
Stage 7  원장 편곡           ★   구간 재생성·직접 편집
```

★ 는 사람이 개입하는 지점이다. **품질을 결정하는 것은 모델이 아니라 이 파이프라인의 설계**다.

## 작곡 엔진 세 가지

파이프라인은 어느 엔진인지 모른다 — 같은 `ComposerEngine` Protocol 을 구현한다.

| 엔진 | 언제 | 검증기·지표 |
|---|---|---|
| `ClaudeComposerEngine` | 운영. `.env` 에 API 키가 있으면 자동 | 그대로 적용 |
| `SessionComposerEngine` | Claude Code 세션이 직접 작곡 (API 미호출) | 그대로 적용 |
| `StubComposerEngine` | 테스트·CI·오프라인 데모 | 그대로 적용 |

세션 엔진 사용법과 산출물은 [docs/SESSION_ENGINE.md](docs/SESSION_ENGINE.md).
실제로 만든 **20곡**(22~96마디 · 난이도 2.8~8.4 · 전곡 하드 검증 통과)의
결과·비용은 [runs/golden/SUMMARY.md](runs/golden/SUMMARY.md). 개선 전 판은 `runs/golden-v1/`.

**API 키는 프로젝트 `.env` 파일에서만 읽는다.** 시스템 환경변수는 쓰지 않는다.

## 빠르게 돌려보기

```bash
cp .env.example .env          # ANTHROPIC_API_KEY 를 넣는다. 없으면 규칙 기반 스텁으로 돈다
make venv && make check-tools # 외부 도구 점검
make test                     # 166건
make demo-m3                  # 모티브 → 설계 → 작곡 → 채점 → 비평, 전 과정 출력
make demo-judge               # 모의 심사 3인
make golden                   # 골든 20건 회귀 → docs/golden-report.md
```

화면은 API 를 띄우고 `web/index.html` 을 브라우저로 열면 된다. 결과 화면에서
악보를 보면서 들을 수 있다 — 양손/오른손/왼손 분리, 템포 조절, 마디 이동.
악보 창은 두 가지다.

- **간이 악보(내장)** — 음표열만으로 대보표를 직접 그린다. 외부 파일도 인터넷도 필요 없어
  **항상 보인다**. 재생하면 지금 마디가 칠해지고 그 안을 세로 막대가 지나며, 악보의
  아무 마디나 누르면 그 자리부터 다시 들려준다(네비게이션).
  음자리표·조표·박자표를 앞머리에 그리고, 조표에 든 음과 한 마디 안에서 이미 적은 음은
  임시표를 반복하지 않는다 — 그래야 표가 아니라 악보로 읽힌다. 셈여림(바뀔 때만),
  이음줄, 스타카토·악센트·테누토·마르카토, 페달 구간도 함께 나온다.
- **악보에서 편집** — 음표를 위아래로 끌면 음높이가 바뀐다. 누른 뒤 ↑ ↓ 키로도 옮기고,
  Shift 를 누르면 한 옥타브씩 간다. 새 음이름은 조표에 맞춰 지어진다(올림표 셋인 곡에서
  '파' 자리로 옮기면 '파♯'). 저장은 M4 편집기와 **같은 경로**를 타서 검증기·지표가
  다시 돌고, 하드 규칙을 어기면 그 자리에서 알려 준다(절대 규칙 2).
- **정식 악보(OSMD)** — 새김 품질. `scripts/fetch_vendor.py` 가 `web/vendor/` 에 받아 두면
  (설치 스크립트가 자동으로 실행한다) 인터넷 없이도 켜지고, 없으면 탭이 꺼진 채
  간이 악보로 본다. 재생 커서는 두 악보 모두에서 따라간다.

소리는 Tone.js 피아노 샘플로 나고, 못 받으면 브라우저 내장 음원으로 계속된다.

## 이름과 저작권 — 곡으로 돈을 벌기 위한 부분

곡을 만드는 것과 곡으로 돈을 버는 것은 다른 일이다. 뒤쪽은 **이름과 권리**가 정리돼야
시작된다.

- **예명 / 실명** — 악보 표지·MP3 태그·콩쿨 제출본에 찍히는 이름은 **예명 하나**다(기본
  `accelssam`). 실명·생년월일·주소는 **저작권 등록 신청서에만** 쓰이고, 프롬프트로도
  악보로도 나가지 않는다(`server/tests/test_rights.py` 가 지킨다). 저장 위치는 이 PC 의
  SQLite 파일뿐이다.
- **창작곡 / 편곡** — 곡마다 어느 쪽인지 적는다. 편곡이면 원곡 제목·작곡가·권리 상태를
  반드시 적어야 하고, **보호 기간 중인데 허락이 없거나 상태를 확인하지 않았으면 막는다**.
  여기서 막지 않으면 등록 반려로 끝나지 않고 저작권 침해가 된다(작곡가 사후 70년).
- **등록 신청서 초안** — 채워야 할 항목을 문서로 만들어 준다. 그대로 제출하는 서식은
  아니고 옮겨 적을 내용이다 — 서식은 위원회 쪽이 바뀌므로 흉내 내지 않는다.

## 판 되돌리기 · 저장 방식

- **판 되돌리기** — 편곡·직접 편집을 할 때마다 판이 하나씩 쌓이고, 아무 판으로나
  돌아갈 수 있다. 되돌리기도 **한 판으로 쌓는다** — 덮어쓰지 않으므로 되돌린 뒤
  마음이 바뀌면 다시 앞으로 갈 수 있다. 편곡을 마음 놓고 시도하게 하는 것이 목적이다.
- **저장은 요청 밖에서** — 저장은 버킷 전체를 다시 직렬화하는 일이라 곡이 쌓일수록
  느려진다(200곡에 1.9초). 그것을 요청 경로에 두면 곡이 늘수록 버튼 하나가 느려지므로,
  표시만 해 두고 일꾼 하나가 몰아서 저장한다. 연달아 눌러도 저장은 한 번이면 된다.
  끄기 버튼과 종료 훅이 동기 저장을 하므로 정상 종료에서는 아무것도 잃지 않는다.
- **백업은 개수와 크기를 함께 본다** — 곡 200개면 저장 파일 하나가 73MB 다. 개수로만
  제한하면 사본이 2GB 가까이 쌓여 집 PC 디스크를 먹으므로 전체 400MB 로 묶는다.
  다만 가장 최근 셋은 크기와 상관없이 남긴다 — 사본이 하나도 없는 것이 최악이다.

## 지도용 악보 — 원장이 가르칠 수 있는 판

이 곡을 사 가는 사람은 학원 원장이고, 그는 곡을 치는 게 아니라 **아이에게 가르친다**.
그래서 악보를 두 벌 낸다.

- **연주용** — 음표만 있는 깨끗한 판. 아이에게 주는 것.
- **지도용** — 손가락 번호와 지도 요점이 얹힌 판. 원장이 보는 것.

두 벌을 한 파일에 섞으면 아이 악보가 지저분해지고, 지도용만 주면 무대에 올릴 것이
없다. 표기는 music21 정식 객체(`Fingering`·`TextExpression`)로 얹으므로 MuseScore 에서
열어 **그 자리에서 고쳐 쓸 수 있다** — 그림으로 그려 넣으면 못 고친다.

지도 표기는 두 갈래다.

- **손가락 번호**(`analysis/teaching.py`) — 규칙으로 계산한 **제안**이다. 올라가는
  음계에서 5 다음에 엄지를 넣고, 큰 도약에서는 손 위치를 옮긴다. 화면·악보·메모
  세 곳에 "제안이므로 아이 손에 맞게 고쳐 쓰라" 고 적는다. 없는 것보다 훨씬 낫지만
  있다고 속이지도 않는다.
- **아이가 걸리는 자리** — 악보에서 **센 것**이라 의견이 아니다. 8반음 이상 도약,
  9반음 이상 벌어지는 화음, 한 마디에 임시표 3개 이상, 새 리듬이 처음 나오는 자리,
  클라이맥스, 곡 전체의 최고음. 각각 "어떻게 가르치나" 를 한 줄로 붙인다.

화면의 `가르칠 때 짚을 곳` 에서 마디 번호를 누르면 그 자리부터 들려준다.

## 레벨별 묶음 · 이번 달 비용

- **묶음 생성** — 레벨을 `3,5,7` 처럼 적으면 그 레벨마다 한 곡씩 만든다. 컨셉은
  겹치지 않게 고르고(같은 컨셉 다섯 곡은 형제 같은 곡이 된다), 제목이 겹치면 컨셉
  이름을 붙여 가른다 — 같은 이름의 상품을 여럿 내놓을 수는 없다. 한 곡이 막혀도
  나머지는 계속 만들고, 막힌 곡은 왜 막혔는지 표에 남는다.
- **이번 달 비용** — 곡을 만들 때마다 날짜와 금액을 남겨 달별로 더한다. 곡당 얼마인지만
  알면 달이 끝나야 총액을 안다. 규칙 기반(무료)으로 만든 곡은 0원이라 자연히 빠진다.

## 제목 · 인쇄 · 백업

- **곡 제목** — 파는 곡의 제목은 상품명이다. 결과 화면 위 칸에서 바꾸면 악보·음원
  태그·판매 꾸러미·저작권 등록 초안이 **모두 같은 이름**을 쓴다. 제목 계산이 여러
  군데 흩어져 있으면 파일마다 다른 이름이 찍히므로 `Store.title_of()` 한 군데로 모았다.
  비우면 프로그램이 지은 이름으로 돌아간다.

- **악보 인쇄 · PDF** — `악보 인쇄 · PDF` 를 누르면 **표지 한 장 + 악보**가 인쇄된다.
  인쇄 창에서 프린터 대신 `PDF로 저장` 을 고르면 그대로 PDF 파일이 된다 — MuseScore
  없이도 인쇄·배포가 된다. 표지에는 부문·제목·작곡가(예명)·연주자·조성·박자·빠르기·
  길이·난이도가 들어간다. 학생 이름은 **반드시 `display_name()` 을 거친다**(절대 규칙 7)
  — 악보 표지는 밖으로 나가는 산출물이라 동의 없는 본명이 실리면 안 된다.

- **자동 백업** — 만든 곡·심사 결과·권리 정보·제목이 전부 `data/store.sqlite3` **파일
  하나**에 있다. 그 파일이 지워지면 전부 사라지므로 저장될 때마다 `data/backups/` 에
  사본을 남긴다(최소 5분 간격, 내용이 늘었을 때만). 최근 12개 + 하루에 하나씩 14일치를
  남기고 나머지는 지운다. 사본은 sqlite 백업 API 로 뜨므로 **그대로 열리는 데이터베이스**다.
  되돌리기는 프로그램이 하지 않는다 — 잘못 되돌리면 지금 것까지 잃기 때문에, 어느
  파일을 어떻게 되돌리는지 화면에서 글로 알려 주고 판단은 사람이 한다.

## 판매 꾸러미 — 압축 하나로 보낸다

`판매 꾸러미 내려받기` 를 누르면 곡 제목 폴더 하나가 압축돼 나온다.

    작은 행진/
      읽어보세요.txt      ← 받는 분이 먼저 읽는 글
      연주.mp3            ← 어느 기기에서나 열린다
      작은 행진.musicxml   ← MuseScore 로 열어 인쇄
      작은 행진.mid        ← 손 나눠 연습용
      연주법 해설.md       ← 해설을 만들어 뒀다면
      곡 정보.md
      권리 정보.md

받는 쪽(다른 학원 원장)은 이 프로그램을 모른다. 그래서 `읽어보세요.txt` 에 무엇이
들었고 무엇부터 열면 되는지, 악보를 인쇄하려면 무엇을 깔면 되는지까지 적어 보낸다.
권리가 정리되지 않은 곡은 꾸러미 안에 그 사실을 크게 적는다 — 막지는 않지만
모르고 파는 일은 없어야 한다.

보관함 목록에도 곡마다 `창작곡` / `편곡 · 정리됨` / `원곡 확인 필요` 가 붙는다.

## 설치하면 바탕화면에 아이콘이 생긴다

`install.ps1`(윈도우) · `install.sh`(맥·리눅스)가 바탕화면과 시작 메뉴에 **콩쿨 작곡기**
아이콘을 만든다. 두 번 누르면 검은 명령창 없이 서버가 뜨고 브라우저가 열린다
(`scripts/launch.py`). 이미 켜져 있으면 서버를 새로 띄우지 않고 창만 연다.
끄는 것은 화면 오른쪽 위 **끄기** 버튼이다 — 명령창이 없으니 Ctrl+C 를 누를 곳도 없기
때문이다.

**음원 내려받기** — 곡을 MP3(없으면 WAV) 파일로 뽑는다. 학생·학부모 휴대폰에서
그냥 열리는 형태라 MIDI 와 달리 재생기를 가리지 않는다. 사운드폰트나 fluidsynth 없이
`server/app/export/audio.py` 가 배음별 감쇠를 직접 합성한다 — 배음마다 잦아드는 속도가
다른 것이 피아노 소리의 핵심이고, 그것만 지키면 외부 프로그램 없이도 들을 만한 소리가
나온다. 셈여림·스타카토·페달이 그대로 반영되고, 화면의 양손/오른손/왼손 선택이
파일에도 적용돼 손 분리 연습 음원을 바로 만들 수 있다.

만든 곡과 올린 코퍼스는 `data/store.sqlite3` 에 남는다 — 서버를 껐다 켜도 사라지지 않는다
(`STORE_PERSIST=0` 이면 예전처럼 메모리만 쓴다).

```bash
cd server && ../.venv/bin/python -m uvicorn app.main:app --port 8000
# 다른 터미널에서
python3 -m http.server 8080 --directory web    # → http://localhost:8080/index.html
```

전체를 컨테이너로 띄우려면 `make up` (web · api · worker-py · db+pgvector · redis).

GET  /api/presets?student_id=...                    컨셉 카드 12가지(학생에 맞는 것 표시)

POST /api/requests/{id}/motifs/custom               원장이 직접 그린 모티브

PATCH /api/requests/{id}/plan                       원장이 고친 설계 재검사
POST /api/requests/{id}/realize                     Stage 3~5 실현·채점·비평 루프
GET  /api/compositions/{id}/musicxml|quality|measures
POST /api/compositions/{id}/judge                   모의 심사 3인
POST /api/recitals                                  연주회 순서·대비 검사·러닝타임

POST /api/corpus                                    참고 악보 업로드(MusicXML/MIDI) → StyleProfile
GET  /api/corpus · GET /api/corpus/{id}/profile     라이브러리 · 특징 벡터
POST /api/corpus/search?request_id=...              이 요청에 붙을 참고곡 미리보기
POST /api/compositions/{id}/guide                   §6.6 연주법 해설(4주 연습 계획·암보 구획)

작곡할 수 없다.

## 콩쿨 입상에 대해

입상은 곡 · 학생의 연주 · 심사위원의 취향이 함께 만든다. **어떤 소프트웨어도 이를
보장할 수 없다.** 이 시스템이 하는 일은 입상 확률을 구조적으로 높이는 것이다 —
부문 규정을 어기지 않게 하고, 학생의 강점이 드러나는 구간을 설계하고, 심사위원이 듣는
첫 8마디와 클라이맥스와 마무리를 강하게 만들고, 모의 심사로 약점을 미리 찾고,
실제 대회 결과를 기록해 다음 곡에 반영한다.

대회마다 창작곡 허용 여부와 악보 제출 규정이 다르다. **곡을 만들기 전에 요강을 확인하고
콩쿨 프로필에 입력하라.** `original_allowed=false` 인 대회는 생성이 차단된다.
