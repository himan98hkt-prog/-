# ConcoursComposer — 구성과 기능

이 문서 하나면 **무엇을 하는 프로그램인지 · 어떻게 설치·실행하는지 · 안이 어떻게
생겼는지 · 무슨 기능이 있는지** 를 다 알 수 있다.
명세는 [SPEC.md](../SPEC.md), 구현 범위는 [SCOPE.md](SCOPE.md), 진행 상황은 [STATUS.md](STATUS.md).

---

## 1. 한 문장

원장이 **학생 한 명의 수준·손 크기·강점·약점과 콩쿨 부문 규정**을 넣으면,
그 학생만을 위한 **피아노 독주 콩쿨곡**을 MusicXML·MIDI 로 만들어 준다.

핵심 주장은 "언어모델이 곡을 잘 쓴다" 가 아니라 **"작곡가가 일하는 순서를 코드로
강제하고, 통과하지 못한 악보는 저장하지 않는다"** 이다.

---

## 2. 설치

인터넷과 **Python 3.12 이상**만 있으면 된다. 관리자 권한은 필요 없다.

```bash
# macOS · Linux
./install.sh        # 파이썬 확인 → .venv → 의존성 → .env 생성 → 자기 점검
./start.sh          # API 서버 + 화면을 한 포트(8000)로 띄운다
```

```powershell
# Windows
.\install.ps1
.\start.ps1
```

`start` 가 뜨면 브라우저에서 **http://localhost:8000** 을 연다. 같은 포트에서
화면과 API 가 함께 서빙된다(`/docs` 는 자동 생성 API 문서).

### API 키

`.env` 파일의 `ANTHROPIC_API_KEY` 한 줄만 채우면 실제 작곡 엔진이 켜진다.
**키는 프로젝트 `.env` 에서만 읽는다 — 시스템 환경변수는 절대 읽지도 쓰지도 않는다**
(`server/app/config.py: read_api_key_from_env_file`). 키가 없으면 규칙 기반
스텁 엔진으로 전 과정이 그대로 돌아간다(품질은 낮지만 흐름·검증은 동일).

### 개발자용

```bash
make venv && make test     # 166건
make lint                  # ruff + mypy strict
make golden                # 골든 20건 회귀 → docs/golden-report.md
make demo-m3               # 모티브→설계→작곡→채점→비평 전 과정 콘솔 출력
make up                    # 도커 6개 서비스(web·api·worker·pgvector·redis)
```

## 3. 구성

```
concours-composer/
├─ install.sh / install.ps1      설치 (venv · 의존성 · .env · 자기 점검)
├─ start.sh   / start.ps1        실행 (API + 화면을 한 포트로)
├─ web/index.html                원장 화면 — 빌드 없는 단일 파일 UI
├─ server/app/                   FastAPI 서버 (아래 표)
├─ server/tests/                 166건 · golden/ 에 회귀 20건
├─ data/store.sqlite3            만든 곡·코퍼스·피드백 (껐다 켜도 남는다)
├─ runs/golden/                  세션 엔진이 실제로 만든 20곡 전체 산출물
└─ docs/                         SCOPE · STATUS · SESSION_ENGINE · 이 문서
```

|---|---|---|

| `generation/prompts/` | 작곡가·비평가 프롬프트(마크다운). **코드에 프롬프트 문자열 금지** | `motif.md` `plan.md` `realize_phrase.md` `critic.md` |

| `api/` | HTTP 경계. 워크플로 순서를 URL 로 강제 | `compositions.py` `corpus.py` `judge.py` … |

### 작곡 파이프라인 (§7.3)

```
Stage 0  컨텍스트     학생 하드 제약 + 콩쿨 규정 + 코퍼스에서 찾은 참고 스타일
Stage 1  모티브 4안 ★ 원장이 듣고 고른다. 고른 모티브는 잠기고 이후 전 단계가 참조
Stage 2  설계(Plan) ★ 형식·마디별 화성·클라이맥스·쇼케이스 구간
                     → 규칙 검사 + 같은 학원의 이전 곡과 형식 지문 대조
Stage 3  실현        2~8마디 프레이즈 단위로 순차 생성. 앞 8마디를 문맥으로 받는다
Stage 4  조립        JSON → music21 → MusicXML 3.1  (결정적, LLM 미개입)
Stage 5  채점·비평   지표 9종 + 별도 호출 비평가 10항목 → 미달 프레이즈만 재생성
Stage 6  후처리      제목 · 연주법 해설 · 모의 심사 3인
Stage 7  원장 편곡 ★ 구간 재생성 · 직접 편집 · 피드백 기록
```

★ = 사람이 개입하는 지점. **LLM 은 절대 MusicXML 문자열을 직접 만들지 않는다.**
언제나 `LLM → JSON → music21 → MusicXML`.

## 4. 기능

### 4.0 대시보드 — 컨셉 버튼 하나로

`http://localhost:8000` 을 열면 **대시보드**가 먼저 나온다.

1. 학생을 적고 **[이 학생으로 컨셉 보기]**
2. **컨셉 카드 12가지**(행진곡·왈츠·노래하는 소품·토카타·주제와 변주·소나티네·론도·
   야상곡풍·춤곡·연습곡풍·아주 작은 소품·피날레) 중 하나를 누른다.
   학생 레벨과 약점에 맞지 않는 컨셉은 흐리게 표시하되 **숨기지는 않는다** —
   원장이 일부러 어려운 성격을 고를 수 있어야 한다.
3. 모티브 고르기 → 설계 → 프레이즈 작곡 → 비평 루프 → **사전 전문심사**까지 한 번에 돈다.
   단계를 건너뛰지 않는다. 고르는 주체가 사람에서 지표로 바뀔 뿐이다.
4. 곡이 나오면 그 자리에서 **악보를 보고 · 듣고 · 편곡**한다.

**사전 전문심사 게이트** — 모의 심사위원 3인이 곡을 내놓기 **전에** 채점한다.
평균 8.0 · 최저 7.0 을 둘 다 넘어야 '심사 통과' 다(`.env` 의 `JUDGE_GATE_AVERAGE`,
`JUDGE_GATE_MINIMUM` 으로 바꾼다). 미달이면 심사위원 **둘 이상이 같은 취지로 지적한**
마디를 겨냥해 한 번 더 고쳐 보고, 그래도 미달이면 '초안' 으로만 표시한다.
한 명의 취향은 취향이지 결함이 아니므로 실행하지 않는다.

**편곡** — 마디 범위와 지시("왼손을 한 옥타브 내려라")를 주면 그 구간만 다시 쓴다.
지정한 마디 밖은 한 음도 건드리지 않고, 이전 판이 남으므로 되돌릴 수 있다.

단계마다 직접 개입하고 싶으면 상단의 **[단계별로 만들기]** 탭이 예전 워크플로 그대로다.

### 4.1 작곡

- **학생 맞춤 하드 제약** — 손 스팬(최대 음정), 음역, 최대 템포, 임시표 비율,
  제한 시간. 어기면 저장 거부.
- **실현 가능 난이도 대역** — 요청 즉시 "이 템포·조표·손 크기로는 난이도 2.1~9.2 만
  가능하다" 를 계산해 알려준다. 불가능한 목표를 받고 나서 실패하지 않는다.
- **모티브 4안 + 즉시 미리듣기** — 화면에서 바로 들어보고 고른다.
- **원장이 직접 그린 모티브** 도 받는다.
- **설계 승인·수정** — 형식·마디별 화성·클라이맥스 위치를 표로 보고 고칠 수 있다.
- **3안 비교** — 같은 모티브로 최대 3안을 만들고 종합 점수 최고안을 기본 표시.
- **가변 프레이즈 길이**(2~8마디) · **제한 시간의 55~85% 를 채우는 길이 설계**.

### 4.2 품질 장치 (이 프로그램의 본체)

| 층 | 무엇을 막는가 |
|---|---|
| **검증기** §7.6 | 마디 길이·손 스팬·음역·손 교차·기보 가능한 음길이·제한 시간·종지·임시표 비율·표절 n-gram·콩쿨 규정. 하나라도 어기면 **저장되지 않는다** |
| **음악성 9지표** §7.4 | 모티브 일관성 · 반복/변화 균형 · 선율 윤곽 · 화성 일치 · 프레이즈 호흡 · 다이내믹 곡선 · 텍스처 대비 · 연주 편의 · 표현 다양성 |
| **난이도 점수** §7.7 | 밀도·스팬·동시음·조표·임시표·템포·리듬 어휘·왼손 텍스처·손 이동 9특징의 가중합. 목표에서 ±1.0 벗어나면 하드 실패 |
| **비평 루프** §7.5 | 작곡가와 **다른 프롬프트·다른 호출**의 비평가가 10항목 채점 + 마디 범위별 수정 지시 |
| **겨냥 수정 라운드** | 종합 점수가 문턱을 넘어도 개별 루브릭이 7.0 아래면 그 항목만 다시. 좋아지지 않으면 **원본을 유지하고 그 사실을 기록** |
| **곡 사이 다양성** | 형식 지문(종지 공식·프레이즈 길이열·모티브 처리·클라이맥스 위치)이 같은 학원의 이전 곡과 0.60 이상 겹치면 **Plan 단계에서 하드 실패** |
| **모의 심사** §6.13 | 성향이 다른 심사위원 3인이 채점하고 "곡에서 고칠 점" 과 "연습에서 보완할 점" 을 분리 |
| **골든 회귀** §7.8 | 요청 20건의 검증 통과율·음악성·비평 총점을 기록. 프롬프트를 바꾸면 이 표를 비교 |
| **저작권 가드** | `copyrighted` 코퍼스의 음표열은 **어떤 프롬프트에도 들어가지 않는다**(전용 테스트로 고정) |

### 4.3 곡이 나온 뒤

- **악보 보기·듣기** — OSMD 렌더 + Tone.js 살라만더 피아노. 양손/오른손/왼손 분리,
  템포 조절, 마디 커서. (CDN 이 막히면 브라우저 내장 음원으로 폴백)
- **MusicXML 3.1 · MIDI 내려받기** — MIDI 는 손별 트랙 분리.
- **연주법 해설** §6.6 — 4주 연습 계획, 암보 구획, 구간별 주의점.
- **제목 후보 3 + 추천**.
- **모의 심사 결과** — 3인의 점수와 코멘트.
- **연주회 프로그램** — 순서·대비 검사·러닝타임.

### 4.4 학원 운영

- **참고 악보 폴더** — `data/reference_scores/` 에 MusicXML·MIDI 를 넣어 두면
  **서버가 시작할 때 자동으로 읽는다**. 업로드 화면을 거치지 않아도 되고, 하위 폴더
  이름은 부문 태그가 된다. 수동으로 다시 훑으려면 `python scripts/import_scores.py`.
  저작권 표시(`같은이름.json`)가 없으면 **저작권곡으로 간주**한다 — 안전한 쪽이 기본값이다.
- **코퍼스** — 올라온 악보에서 StyleProfile 을 뽑아 요청마다 비슷한 곡을 찾아
  컨텍스트에 넣고, 표절 n-gram 검사의 대조 대상이 된다. 저작권곡은 **통계만 쓰고
  음표열은 보관조차 하지 않는다**.
- **생성곡 자동 등록** — 만든 곡이 코퍼스에 들어가 다음 곡의 표절·다양성 검사 대상이 된다.
- **원장 피드백** — 👍/👎 · 이유 태그 · **실제로 손댄 마디** 를 그때의 지표와 함께 얼려 저장.
  표본 30건이 모이면 가중치 보정(M8).
- **대회 결과 기록** — 실제 입상 결과를 넣어 다음 곡에 반영.
- **학생 이름 보호** — 외부로 나가는 산출물은 `media_consent` 를 검사하고 동의가 없으면 마스킹.

### 4.5 작곡 엔진 3종

파이프라인은 어느 엔진인지 모른다 — 같은 `ComposerEngine` Protocol 을 구현한다.
**검증기·지표·비평 루프는 어느 엔진이든 똑같이 적용된다.**

| 엔진 | 언제 쓰나 |
|---|---|
| `ClaudeComposerEngine` | 운영. `.env` 에 키가 있으면 자동. 프롬프트 캐싱·Batch 옵션·토큰 로깅 |
| `SessionComposerEngine` | Claude Code 세션이 직접 작곡(API 미호출). `runs/golden/` 의 20곡이 이것 |
| `StubComposerEngine` | 테스트·CI·오프라인 데모 |

## 5. 실제로 만든 20곡

`runs/golden/SUMMARY.md` 가 전부다. 20곡 모두 **하드 검증 통과**.

병행 5·8도는 곡마다 0~12건 남아 있다(소프트 경고 — 저장을 막지 않는다). 예전에는
전곡 0건이었는데, 그것은 검사가 **마디의 첫 음만** 봤기 때문이다. 마디 안의 병행까지
보도록 고치자 20곡 합계 123건이 드러났고, 다듬기 루프가 왼손 자리바꿈으로 92건까지
줄였다. 남은 것은 루프가 "고쳐도 곡이 나아지지 않는다" 고 판단해 원본을 유지한 자리다.

| 항목 | 범위 |
|---|---|
| 마디 | 22 ~ 96 |
| 연주 시간 | 제한 시간의 55 ~ 78% |
| 음악성 | 9.02 ~ 9.64 |
| 병행 5·8도(소프트) | 0 ~ 12건 |
| 비평 총점 | 7.8 ~ 8.55 |
| 종합 | 8.41 ~ 8.78 |
| 난이도 | 2.82(유치·초등저) ~ 8.42(중등) |

곡마다 `motif_prompt.md` 부터 `score.musicxml` · `score.mid` · `validation.json` ·
`quality.json` · `judge.json` · `guide.json` 까지 전 과정이 남아 있다.

## 6. 한계 (정직하게)

- **입상을 보장하지 않는다.** 입상은 곡·연주·심사위원 취향이 함께 만든다.
  이 시스템은 규정 위반을 막고, 강점이 드러나는 구간을 설계하고, 첫 8마디·클라이맥스·
  마무리를 강하게 만들어 **확률을 구조적으로 올릴** 뿐이다.
- **피아노 2단 보표만** 지원한다. 다른 악기·앙상블은 범위 밖.
- **채보·시각화·릴스(SPEC §6.10~6.12)는 원장 결정으로 제외**했다(docs/SCOPE.md).
- **마우스 악보 편집(M4)은 아직 없다.** 구간 편곡은 대시보드와 API 로 가능하지만,
  음표 하나를 끌어 옮기는 편집은 M4 다.
- 화면은 아직 무빌드 단일 파일이다. Next.js 전환 계획은 `web/README.md`.
- 피드백 기반 **가중치 보정은 표본 30건 뒤**(M8)에 켜진다. 지금은 수집만 한다.
- 대회마다 창작곡 허용 여부가 다르다. **곡을 만들기 전에 요강을 확인하고 콩쿨 프로필에
  입력하라.** `original_allowed=false` 인 대회는 생성이 차단된다.
