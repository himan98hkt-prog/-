## 2. 화성 확인 화면

지시서 10장이 요구한 것을 하나씩 대조한다.

| 요구 | 구현 | 확인 방법 |
|---|---|---|
| **음표가 아니라 화음 이름만** | 서버가 음표를 아예 안 보낸다 | `test_view_carries_no_notes_only_chords` 가 응답에 pitch/midi/octave 가 없음을 확인 |
| 각 칸은 드롭다운 | 조성의 화음 16개가 먼저, 그 외 32개가 뒤에 | 브라우저 실측: K.545 에서 드롭다운 18개 |
| 바꾸면 **즉시 반주 재생성** | 화음이 바뀌면 렌더 키가 바뀌어 자동 재생성 | `test_changing_a_chord_changes_the_audio` |
| 자신 없는 구간 **노란색** | 1위–2위 점수 차(`conf`)가 작은 칸 + "다음 후보" 표시 | 브라우저 실측: 바흐 전주곡 34마디 중 12칸 노란색 |
| 해당 마디만 **구간 재생** | 마디마다 ▶ 버튼 | 브라우저 실측 (아래) |
| **조성 확인 UI 는 불필요** | 없다 | — |

### 구간 재생은 서버를 다시 부르지 않는다

한 번 받은 mp3 안에서 건너뛴다:

```
초 = 마디 시작(4분음표 단위) × 60 / bpm
```

템포가 일정하므로 이 환산이 정확하다. 브라우저 실측 — ♩=126 곡의 3번 마디
(8.0박 지점)에서 **3.81초**에 시작해 **5.88초**에 멈췄다 (기대 3.81 / 5.71,
정지 오차는 `timeupdate` 폴링 간격).

덕분에 마디를 아무리 여러 번 들어도 렌더는 한 번뿐이다.

### 검수 부담이 실제로 얼마나 줄어드는가

지시서는 "음표 단위 40분 → 화성만 3~5분"이라고 한다. 사람이 실제로 몇 분 걸리는지는
아직 재지 못했다(써 본 사람이 없다). 대신 **봐야 할 칸이 몇 개인지**는 쟀다.

| 곡 | 마디 | 칸 | 노란색 | 비율 |
|---|---|---|---|---|
| 클라라 슈만 폴로네즈 Op.1-2 | 96 | 128 | 6 | 5% |
| 클라라 슈만 폴로네즈 Op.1-1 | 84 | 108 | 14 | 13% |
| 클라라 슈만 폴로네즈 Op.1-3 | 64 | 100 | 15 | 15% |
| 바흐 평균율 1권 1번 전주곡 | 34 | 37 | 12 | 32% |
| 모차르트 K.545 1악장 제시부 | 12 | 18 | 2 | 11% |
| **전체 26곡** | — | **764** | **78** | **10%** |

96마디짜리 폴로네즈도 실제로 판단해야 할 칸은 6개다. 나머지는 훑고 넘어간다.

화면은 곡별 **검수 시간을 자동 누적**하므로, 실제 20분 목표는 카탈로그를 채우면서
`catalog_cli.py status` 로 바로 확인된다 (평균·20분 초과 곡 수).

### 바흐 전주곡에서 노란색이 어디에 붙었나

엔진이 헷갈린 자리가 실제로 헷갈릴 만한 자리인지가 중요하다. BWV846 에서:

- m2 → `F` (노란색, 다음 후보 C/Am). 교과서 답은 **Dm7/C** — 7화음이라 삼화음
  후보로는 못 맞힌다. 사람이 고칠 자리로 정확히 표시됐다
- m3 → `Bdim` (노란색). 실제는 **G7/B** — Bdim 은 G7 의 윗구조다. 역시 표시됨
- m5 → `Am` (노란색) — 실제 Am7/C. 근음은 맞다
- m6 `D7`, m12 `C7`, m22 `D7`, m24 `G7` — 전부 맞다

즉 노란색이 **엉뚱한 데 붙지 않고, 진짜 애매한 데 붙는다.** 확인 화면이 제 역할을
한다는 뜻이다.

## 3. 카탈로그

### 저장 원칙 (지시서 6장)

```
catalog/
  catalog.json          곡 메타 + 확정된 화성 + 검수 상태   ← 백업 대상
  scores/<id>.musicxml  원본 악보                          ← 백업 대상
  midi/<id>.mid         반주 MIDI (1 KB 미만)              ← 백업 대상
  cache/<key>.mp3       렌더 캐시 — 지워도 2초면 다시 생긴다
```

`test_catalog_keeps_midi_not_audio` 가 `catalog.json` 에 오디오 확장자가 섞이지
않는지 확인한다.

### 저작권 방어선 (지시서 7장)

검사를 **파일 복사보다 먼저** 한다. 블랙리스트에 걸리거나 `--public-domain` 이
없으면 악보가 디스크에 남지 않는다 (`test_import_refuses_blacklisted_music_before_copying`).

### 곡 id 는 지어내지 않는다

'체르니 100번 5번' 같은 한글 제목은 ASCII 로 숫자만 남아 `100_5` 라는 쓰레기 id 가
나온다. 곡 id 는 배정·발표회 큐가 물고 가는 **영구 식별자**라, 쓸 만한 게 안 나오면
`--id` 를 요구하고 거부한다.

## 4. 만들면서 잡은 버그

브라우저로 실제로 돌려 보지 않았으면 전부 놓쳤을 것들이다.

| 증상 | 원인 | 왜 위험했나 |
|---|---|---|
| 구간 재생이 8.0초에서 시작 (기대 3.81초) | 곡의 템포 ♩=126 이 드롭다운 보기에 없어 브라우저가 첫 항목 60 을 골랐다 | 그 상태로 저장하면 **곡에 저장된 템포가 조용히 60 으로 덮어써진다.** 화면을 열기만 해도 데이터가 망가진다 |
| 재생 실패가 조용히 사라짐 | `playRange` 안의 저장 실패가 try 밖이라 미처리 거부로 끝났다 | 원장이 아니라 우리가 쓰는 도구지만, 실패를 모르면 안 고친 채로 "확인 완료"를 누른다 |
| 반복기호가 있는 곡의 교정이 두 마디에 동시 적용 | 교정을 `(인쇄된 마디번호, 칸)` 으로 찍었는데 반복을 펼치면 같은 번호가 두 번 나온다 | 1절만 고쳤는데 2절까지 바뀐다 |

## 5. 못 한 것 — 악보 150곡

지시서 2단계의 본체는 **약 150곡**(체르니 100 전곡 + 바이엘 후반 + 부르크뮐러 25)이다.
그 MusicXML 은 MuseScore.com·IMSLP 에서 **사람이 곡마다 확인하며 받아야** 한다.
여기서는 하지 못했다 — 자동으로 긁어올 일도 아니고(라이선스 표기를 곡마다 봐야 한다),
이 환경에서 할 수 있는 일도 아니다.

대신 파이프라인이 실제로 도는 것은 증명했다. 지금 들어 있는 26곡:

- 퍼블릭도메인 피아노곡 6곡 — 바흐 평균율 1권 1번 전주곡, 모차르트 K.545 1악장
  제시부, 클라라 슈만 폴로네즈 Op.1 네 곡 (64~96마디로, 실제 카탈로그 곡 크기)
- 자사 오리지널 연습곡 20곡 — 지시서 7장 화이트리스트의 마지막 항목

악보를 확보하면 다음 한 줄로 들어가고, 나머지는 그대로 돈다:

```bash
python3 catalog_cli.py import burgmuller_02.mxl --title "부르크뮐러 25곡 2번" \
    --id burgmuller_02 --composer "Friedrich Burgmüller" --book "부르크뮐러 25" \
    --level 4 --public-domain --style chamber
```

## 6. 3단계가 쓸 것

- `catalog_cli.py export player.json` — 확인 완료된 곡만, 오디오 없이 내보낸다
  (곡 메타 + 반주 MIDI 경로 + 기본 편성·템포)
- `catalog.Program.cue_lines()` — 발표회 큐 목록 문자열 (모듈 ⑤-3)
- `mr.py --count-in N` — 카운트인 (모듈 ⑤-4)
