# 배포 · 판매 운영

## 1. 빌드

```bash
npm ci
npm test            # 실패하면 배포하지 않는다
npm run build       # dist/
```

산출물:

```
dist/index.html          Pro 앱
dist/lite.html           Lite 앱
dist/tools/keygen.html   판매자 전용 인증키 발급기 (고객 배포 금지)
dist/assets/*            해시가 붙은 JS/CSS
```

체험판을 파일 하나로 보내야 할 때는 `npm run demo` 로 `dist-demo/학원관리노트-체험판.html` 을 만듭니다.
(HTML 안에 JS·CSS 를 전부 넣은 단일 파일이라 메일 첨부·USB 전달로 바로 열립니다)

`base: './'` 상대 경로 빌드라 `https://example.com/note/` 같은 하위 경로에 올려도 그대로 동작합니다.

## 2. 웹호스팅 업로드

1. FTP/파일관리자로 `dist/` 내용을 배포 디렉터리에 업로드
2. **`tools/` 디렉터리는 고객용 배포 경로에 올리지 않습니다.** 판매자 PC 나 접근 제한 경로에서만 사용
3. HTTPS 필수 — 서비스 워커(오프라인)와 홈 화면 설치가 HTTPS 에서만 동작합니다
4. 캐시 정책: `assets/*` 는 파일명에 해시가 있으므로 장기 캐시, `*.html` 은 `no-cache` 권장

업데이트 배포 시 서비스 워커가 "네트워크 우선"으로 동작하므로, 사용자는 새로고침 한 번으로 최신 버전을 받습니다.

## 3. 인증키(시디키) 발급 흐름

1. `dist/tools/keygen.html` 을 판매자 PC 에서 연다
2. 제품(통합 A 권장) · 플랜(Lite/Pro) · 수량을 정해 발급 → CSV 저장 (주문번호를 메모에 기록)
3. 주문 완료 시 고객에게 키 전달
4. 고객이 앱 첫 화면(인증 화면)이나 설정 > 인증키 · 플랜에 입력 → 플랜 자동 활성화
5. 고객 문의 시 발급기 하단 "키 검증"에 붙여 넣어 제품·플랜·유효성 확인

키 체계와 재발급 대응은 [LICENSE-KEYS.md](LICENSE-KEYS.md) 에 정리되어 있습니다.
**통합키(A)** 로 발급하면 피아노 관리노트와 학원 관리노트에서 같은 키를 씁니다.

> 키는 서버 없이 검증됩니다. 폐기(블랙리스트)가 필요하면 Pro 는 `academies.license_key_hash` 로
> 서버 측 차단이 가능하고, Lite 는 구조상 불가하므로 정책으로 관리합니다.
> 백업 파일에는 인증키가 담기지 않으므로 백업을 통한 라이선스 복제는 되지 않습니다.

## 4. Pro 인프라 준비 (학원별이 아니라 전체 1회)

1. Supabase 프로젝트 1개 생성 (무료 티어 기준 설계)
2. SQL Editor 에서 `supabase/schema.sql` 실행
3. Authentication > Providers > **Anonymous sign-in 활성화**
4. Project URL / anon key 를 고객 안내문에 포함하거나, 빌드 시 `.env` 에 주입
   (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`)

anon key 는 공개돼도 RLS 로 막히지만, `service_role` 키는 절대 프런트에 넣지 않습니다.

## 5. 피아노 자동 반주(MR) 배포

반주는 **두 덩어리**로 나뉘고, 나가는 것은 한쪽뿐입니다.

| | 누가 쓰나 | 어디서 도나 | 고객에게 나가나 |
|---|---|---|---|
| **카탈로그 제작 서버** (`python3 serve.py`) | 우리 | 우리 PC | ✗ |
| **플레이어 꾸러미** (정적 파일) | 원장님 | 웹호스팅 | ✅ |

원장님 PC 에 파이썬·fluidsynth·SoundFont 를 깔게 할 수는 없습니다. 그럴 필요도
없습니다 — 플레이어가 런타임에 부르는 건 **곡 목록과 반주 MIDI 둘뿐**이고 둘 다 그냥
파일입니다. 그래서 앱이 부르는 **그 경로 그대로** 파일을 깔아 두면 정적 호스트에서
코드 한 줄 안 고치고 돕니다 (지시서 8.4 — *"MIDI 를 클라이언트에 내려주고 브라우저에서
재생하면 서버 렌더링조차 불필요하다"*).

### 꾸러미 만들기

```bash
cd mr
python3 catalog_cli.py package ../dist/반주 --academy "행복피아노"

# 편성을 여러 벌 넣으려면 (곡마다 파일이 하나씩 늘어납니다)
python3 catalog_cli.py package ../dist/반주 --styles chamber,march --levels normal
```

26곡 실측 — **파일 38개, 128 KB** (반주 MIDI 45 KB). 메일 첨부로도 보낼 수 있습니다.

들어가는 것과 안 들어가는 것:

```
들어감   플레이어(HTML/CSS/JS/서비스워커) · 곡 목록 · 반주 MIDI · 발표회 프로그램
안 들어감 악보 원본(scores/) · 렌더 캐시(cache/) · 화성 확인 화면 · PDF 업로드
```

악보 원본을 빼는 건 용량 때문만이 아닙니다. 넣으면 **악보를 재배포하는 모양**이 됩니다
(지시서 7장). 테스트가 이걸 막습니다 — `test_the_package_carries_no_scores_or_cache`.

### 올리기

1. 꾸러미 폴더를 통째로 업로드합니다. `dist/` 옆이든 `/반주/` 같은 하위 폴더든 됩니다.
   주소가 전부 상대경로라 하위 폴더에서도 그대로 돕니다 (`data-api="./"`).
2. **HTTPS 필수.** 서비스 워커(오프라인)와 홈 화면 설치가 HTTPS 에서만 동작합니다 —
   관리노트와 같은 이유입니다.
3. 캐시 정책: `api/player/midi/*` 는 내용이 바뀌면 곡을 다시 구우므로 장기 캐시,
   `index.html` 과 `api/player/bundle` 은 `no-cache` 를 권합니다.

원장님께는 꾸러미 안의 **`읽어보세요.txt`** 를 그대로 안내하시면 됩니다.

### 곡을 추가한 뒤

꾸러미를 다시 만들어 같은 자리에 덮어씁니다. 서비스 워커가 곡 목록을 "네트워크 우선"
으로 보기 때문에 원장님은 **새로고침 한 번**으로 최신 목록을 받습니다. 이미 받아 둔
반주는 그대로 두고 새 곡만 받습니다.

> 꾸러미 버전이 올라가면(`sw.js` 의 `VERSION`) 예전 캐시는 통째로 지워집니다.
> 그때는 원장님이 ⤓ 를 한 번 더 눌러 전곡을 다시 받아야 합니다 — 128 KB 라 금방입니다.

### 검사

```bash
cd mr
python3 catalog_cli.py package /tmp/pkg
python3 tools/player_check.py --static /tmp/pkg
```

`--static` 은 MR 서버가 아니라 **평범한 정적 서버**(`python -m http.server`)로 띄워
11항목을 봅니다. 그 뒤 서버를 죽이고 오프라인 재생까지 확인합니다 — 원장님 PC 에
파이썬이 필요 없다는 것의 유일한 증거입니다.

### 인증키

반주도 **관리노트와 같은 키 한 장**으로 엽니다 (통합키 `A` · 피아노키 `K`).
다만 정적 꾸러미에는 인증이 붙지 않습니다 — 키를 보는 것은 **PDF 업로드 하나뿐**이고
그건 제작 서버 쪽 기능이기 때문입니다. 자세한 것은
[MR-LINK.md](MR-LINK.md) 3장.

## 6. 사용설명서

원장님이 혼자 쓰실 수 있어야 파는 물건이 됩니다. 설명서는 **파일 하나**로 만듭니다 —
메일로 보내거나 USB 에 담아 드릴 수 있어야 하기 때문입니다. 이미지 폴더가 따로 있으면
옮기다 빠지고, 빠지면 그림 없는 설명서가 됩니다.

```bash
npm run manual:shots     # 화면을 다시 찍는다 (관리노트 + 반주)
npm run manual           # dist/manual.html
npm run manual:verify    # 브라우저로 열어 확인 + dist/manual.pdf
```

> 파일 이름을 ASCII 로 두는 이유: 한글 파일명은 FTP·웹호스팅을 거치며 깨지는 일이 있고,
> 그러면 원장님이 여는 **주소 자체가 안 열립니다.** 화면에 보이는 제목은 한글입니다.
> 한글 이름으로 내려받게 하시려면 `--out` 으로 바꿀 수 있습니다.

실측 — **3부 16장 67절, 그림 20장, 자주 하는 실수 25개, 1.4 MB.**
1부 관리노트 · 2부 피아노 반주 · 3부 문제 해결과 부록. 인쇄하면 **A4 37쪽**입니다.

### 검사는 두 겹입니다

`npm run manual` 은 **내보내기 전에 스스로 검사하고, 걸리면 파일을 아예 안 만듭니다** —
반쪽짜리 설명서를 남겨 두면 그게 배포되기 때문입니다. 보는 것: 목차가 없는 곳을
가리키지 않는지, 그림이 전부 문서 안에 들어갔는지, 그림에 `loading` 이 안 붙었는지.

`npm run manual:verify` 는 진짜 브라우저로 열어 봅니다 — 그림이 **실제로 그려지는지**,
목차를 누르면 정말 그 장으로 가는지, 인쇄하면 목차 사이드바가 빠지는지, A4 로
뽑히는지. 덤으로 `dist/manual.pdf` 가 나옵니다(메일로 보내실 때 쓰세요).

> `loading="lazy"` 를 금지하는 이유: 그림이 이미 문서 안에 있어서 미룰 통신이 없는데,
> 미루면 **종이로 뽑을 때 아래쪽 그림이 빈칸으로 나옵니다.** 이 설명서는 원장님이
> 인쇄해 두고 보시라고 만든 것이라 그게 제일 아픈 고장입니다.

### 그림은 손으로 찍지 않습니다

`scripts/shots.mjs`(관리노트)와 `mr/tools/manual_shots.py`(반주)가 데모 데이터를 넣고
실제 화면을 캡처합니다. **손으로 찍으면 화면이 바뀌었을 때 설명서만 조용히 낡습니다.**
화면을 고치셨으면 `npm run manual:shots` 를 다시 돌리고 설명서를 다시 만드세요.

### 원고 고치기

원고는 [`scripts/manual-content.js`](../scripts/manual-content.js) 한 파일입니다.
절 하나가 `{ title, shot, body[], trap }` 이고, `trap`(자주 하는 실수)은 **실제로 겪을
만한 것만** 적습니다 — 지어내면 설명서를 안 믿게 됩니다.

굵게는 `**...**`, 코드는 백틱만 씁니다. 그 외 마크다운 문법은 없습니다.

### 올리기

`dist/` 와 같이 올립니다. 앱에서 링크하시거나 주소를 직접 안내하시면 됩니다.
브라우저에서 바로 인쇄하면 **A4 로 떨어집니다**(장마다 쪽을 나누고 그림·표는 쪼개지
않습니다). 미리 뽑아 둔 `dist/manual.pdf` 를 메일로 보내셔도 됩니다.

## 7. CI

| 워크플로 | 실행 시점 | 하는 일 |
|---|---|---|
| `CI` | push(main), PR | `npm ci` → 테스트 209건 → 프로덕션 빌드 → 산출물 3종 확인 → `dist` 아티팩트 업로드 |
| `브라우저 검증` | 수동 (Actions 탭) | Chromium 설치 후 `npm run smoke` + `node scripts/perf.mjs` → `perf-report.json` 아티팩트 |

브라우저 검증은 20만 건 더미 생성 때문에 10분 이상 걸려 매 PR 자동 실행에서 제외했습니다.
릴리스 전에 한 번 돌리고 아티팩트를 보관하세요.
