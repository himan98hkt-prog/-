# 인증키(시디키) 운영 안내

판매자용 문서입니다. 고객에게 배포하지 마세요.

## 0. 두 제품이 키를 함께 쓰는 방법 (결론)

**새로 파는 키는 발급기의 "공용키(피아노 방식)" 로 만드세요.** 그 키는

- 피아노학원 관리노트에서 **지금 그대로** 열립니다 (그 앱을 고칠 필요가 없습니다)
- 학원 관리노트에서도 열립니다 (이 저장소가 피아노 규칙을 그대로 인정하도록 맞췄습니다)

기존에 팔린 피아노 키도 회수할 필요가 없습니다. 두 방식 모두 학원 관리노트에서 인정합니다.

| 피아노 쪽 발급 방식 | 학원 관리노트에서 | 필요한 것 |
|---|---|---|
| 자기검증 방식 (미리 만들어 둔 키) | 그대로 열림 · **Pro** | 없음 |
| 학원명 방식 (`학원명 → 키`) | 열림 · **Pro** | 인증 화면에서 그 **학원명**을 함께 입력 |

피아노 관리노트에서 발급된 키는 **Pro(여러 기기·실시간 동기화)** 로 인정합니다.
Pro 로 열리므로 기기마다 PIN 을 묻고, 설정에 Supabase 동기화 항목이 나타납니다
(동기화를 설정하지 않으면 한 대에서 오프라인으로 그대로 쓰면 됩니다).

학원명 방식 키로 인증하면 그 학원명이 시작 마법사에 자동으로 채워집니다.

## 1. 키 형식

12자리, 표기는 4자씩 끊어 `APBC-DEFG-1234`.

| 자리 | 뜻 | 값 |
|---|---|---|
| 1 | 제품 | `A` 통합(피아노 관리노트 + 학원 관리노트) · `M` 학원 전용 · `K` 피아노 전용 |
| 2 | 플랜 | `L` Lite(단일 기기·오프라인) · `P` Pro(다기기·실시간 동기화) |
| 3~8 | 랜덤 | Crockford base32 (사람이 헷갈리는 I·L·O·U 제외) |
| 9~12 | 체크섬 | 제품 salt + 본문을 해시한 값 — 한 글자만 틀려도 거부 |

초기 발급분(첫 자리가 `L`/`P` 인 12자리)도 계속 인정합니다. 굳이 회수하지 않아도 됩니다.

## 2. 피아노 관리노트 키 규칙 (이식 완료)

피아노 발급기(`pambookkey.html`)의 규칙을 `src/core/license-piano.js` 에 **한 글자도 바꾸지 않고** 옮겼습니다.

```
salt   PAL-x7Qm3vK9nR-accelssam-2026
문자표 ACDEFGHJKLMNPQRTUVWXY34679   (26자 · L·U 를 쓰고 0·1·2·5·8 은 쓰지 않음)
학원명 방식   키 = base26( hash(salt|정규화한 학원명|salt) ) 12자
자기검증 방식 앞 8자 무작위 + 뒤 4자 = base26( hash(salt#SV#앞8자) )
학원명 정규화 공백·괄호·가운뎃점·마침표·쉼표·하이픈 제거 후 소문자
```

원본과 같은 값이 나오는지는 테스트로 고정해 두었습니다(`tests/license-piano.test.js`).
실제 발급기가 뽑은 키를 기준값으로 박아 두었으므로, 이 값이 깨지면 테스트가 먼저 실패합니다.

| 학원명 | 키 |
|---|---|
| 아첼음악학원 | `XVXA-FGGN-97KU` |
| 가온피아노학원 | `FQQH-9TRV-XTAV` |
| 아첼 음악학원 (강남) | `RNUP-GUGG-NURQ` |

> ⚠️ `PIANO_SALT` 와 `PIANO_CHARS` 는 **이미 판매된 고객 키를 여는 열쇠**입니다. 절대 수정하지 마세요.

### 학원 관리노트 키를 피아노 앱에서도 열려면

`integration/piano/학원관리노트-키-인정-패치.js` 를 피아노 앱의 기존 라이선스 코드 아래에 붙여 넣고,
키 확인하는 자리에서 `licSelfValid(키)` 를 `licAnyValid(키, 학원명)` 으로 바꾸면 됩니다.
붙이는 절차와 확인용 키는 `integration/piano/README.md` 에 있습니다.

붙이면 통합키(`A…`)와 피아노 전용키(`K…`)가 피아노 앱에서 열리고, 기존 피아노 키는 그대로 동작합니다.
학원 전용키(`M…`)는 의도적으로 거부합니다.

> 새 키를 계속 **공용키(피아노 방식)** 으로만 판다면 이 패치 없이도 한 키로 두 제품이 열립니다.
> 패치는 "학원 관리노트 쪽에서 발급한 키도 피아노 앱에서 받고 싶을 때" 필요합니다.

## 3. 발급 절차

1. `npm run build` 후 `dist/tools/keygen.html` 을 로컬에서 엽니다. (고객 서버에 올리지 마세요)
2. 키 방식(보통 **공용키 — 피아노 방식**) · 수량 · 메모(주문번호)를 넣고 **키 발급**.
   공용키는 두 제품에서 Pro 로 열립니다. Lite 로만 팔고 싶을 때 `A`/`M` 방식 + Lite 를 고릅니다.
3. **CSV 저장** 으로 `key,product,plan,issued_at,memo` 를 보관합니다. 이 파일이 판매 대장입니다.
4. 고객에게는 키 문자열만 전달합니다.

## 4. 고객 화면에서 일어나는 일

- 첫 실행 → 인증 화면. 키 입력 또는 **14일 체험 시작**.
- 인증하면 IndexedDB 설정에 `{키, 키 해시, 플랜, 제품, 기기번호, 인증일}` 이 저장됩니다.
- 체험이 끝나면 다시 인증 화면이 뜨지만 **데이터는 그대로** 남아 있어 키를 넣으면 이어서 씁니다.
- 설정 > 인증키 · 플랜에서 키 교체, 이 기기 인증 해제가 가능합니다.

## 5. 문의 대응

| 상황 | 대응 |
|---|---|
| "키를 잃어버렸어요" | 판매 CSV 에서 주문번호·메모로 조회해 재전달 |
| "기기를 바꿨어요" | 같은 키를 새 기기에 입력하면 됩니다(오프라인 검증이라 횟수 제한 없음). 필요하면 기존 기기에서 인증 해제 요청 |
| "키가 안 들어가요" | 화면의 오류 문구를 물어보세요. `검증번호가 맞지 않습니다` = 오타, `○○ 전용 키` = 제품 불일치, `12자리입니다` = 자릿수 |
| "피아노에서 쓰던 키인데 안 돼요" | 학원명 방식 키입니다. 인증 화면의 "피아노 관리노트 키인가요?" 를 눌러 **학원명**을 함께 넣어야 합니다. 발급기 검증 칸에서 학원명과 함께 확인해 보세요 |
| "몇 번 기기인지 알고 싶어요" | 인증 화면·설정 화면 하단의 6자리 기기번호 |

## 6. 알려진 한계 (정직하게)

- 오프라인 자체검증이라 **키 공유를 기술적으로 막지 못합니다.** 브라우저 앱 특성상 salt 가 클라이언트에 포함되므로,
  작정하고 분석하면 키를 만들어 낼 수 있습니다. 이 방식은 "정품 구매 흐름을 만드는 것" 까지가 목적입니다.
- 강한 통제가 필요하면 Pro(Supabase) 쪽에 서버 검증을 붙이는 것이 정공법입니다.
  `academy_members` 테이블에 키 해시를 저장하고 학원 생성 시 서버에서 검증하는 방식으로 확장할 수 있습니다.
- 백업 파일에는 인증키가 들어가지 않으므로, 백업을 통한 라이선스 복제는 막혀 있습니다.
