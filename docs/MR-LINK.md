## 1. 무엇이 비어 있었나

5단계를 시작하면서 먼저 확인한 것은 **이미 되어 있는 것**이었다.

| | 상태 |
|---|---|
| 통합 인증키(`A`)가 두 관리노트를 함께 여는 구조 | **이미 있었다** (`src/core/license.js`) |
| 피아노 관리노트 쪽에서 학원 키를 인정하는 패치 | **이미 있었다** (`integration/piano/`) |
| **반주(MR)가 학생을 아는 것** | **없었다** — 자유 입력 이름뿐 |
| **반주가 같은 인증키를 인정하는 것** | **없었다** — 인증 개념 자체가 없었다 |

그래서 5단계의 실체는 두 가지다.

## 2. 학생 정보 공유 — 명단이 두 벌이면 안 된다

### 문제

지금까지 반주 쪽은 학생을 **자유 입력 이름**으로 들고 있었다. 원장님은 같은 명단을
관리노트에 한 번, 반주에 또 한 번 친다. 그러면

- 표기가 갈린다 — 「김지우」 / 「김 지우」
- 동명이인이 들어오면 **누구 반주인지 알 수 없다**
- 개명하면 두 군데를 다 고쳐야 한다

발표회 전날 「김지우가 두 명인데 누구 반주죠」가 되지 않게 하는 것이 이 단계의 목적이다.

### 넘기는 것과 안 넘기는 것

관리노트의 학생 레코드에는 이런 것들이 들어 있다.

```js
{ id, name, school, grade, phone, parent_phone, siblings_group,
  status, joined_at, memo, custom, discount, updated_at }
```

**반주를 만드는 데 쓰이는 건 하나도 없다.** 그래서 내보내는 것은 넷뿐이다.

```json
{ "id": "s1", "name": "김지우", "class": "월수금 4시", "active": true }
```

연락처·메모·수납 할인 사유를 같이 넘기면 개인정보가 두 시스템에 흩어지고, 반주 쪽이
털리면 연락처까지 같이 털린다. 테스트가 양쪽에서 이걸 못 박는다.

```js
// tests/roster-piano.test.js — 내보내는 쪽
for (const field of NEVER_EXPORT) expect(blob).not.toContain(field)
expect(blob).not.toMatch(/010-\d/)
```

```python
# mr/tests/test_roster.py — 받는 쪽 (관리노트가 실수로 더 넣어도 디스크에 안 남는다)
for leak in roster.NEVER_KEEP:
    assert leak not in saved, f'{leak} 가 디스크에 남았습니다'
```

10명 명단의 실측 크기는 **834 바이트**, 연락처 0건.

### 이름이 아니라 id 로 연결한다

반주 쪽 발표회 큐가 학생을 이름으로 들고 있으면, 개명하거나 동명이인이 들어오는 순간
연결이 끊긴다. 그래서 `QueueItem` 에 `student_id` 를 붙이고, **화면에 뿌리는 이름은
명단에서 그때그때 찾아 쓴다.**

실측 — 큐에 저장된 이름은 「옛날에 손으로 적은 이름」인데 화면에는 명단의 이름이 나온다:

```
1. 김지우       연결=True   1. 김지우 — 작은 왈츠 (C장조) (♩=84, 동화풍, 보통)
2. 박서준       연결=False  2. 박서준 — 3/8박 작은 노래 (F장조) …
3. 이하은       연결=False  3. 이하은 — 첫 화음 연습 (C장조) …
```

2번은 명단에 없는 학생이다. **그래도 화면이 비지 않는다** — 저장해 둔 이름을 그대로
쓰고 `linked=false` 로 표시한다. 명단을 아직 안 받았거나 그 학생이 빠졌다고 해서
발표회 당일 화면이 비면 안 되기 때문이다.

### 병합이 아니라 덮어쓰기다

명단을 다시 받으면 **통째로 갈아 끼운다.** 관리노트에서 퇴원 처리한 학생이 반주 쪽에
영영 남아 있으면 발표회 명단에 유령이 낀다. 관리노트가 원본이다.

```
$ python3 catalog_cli.py roster 행복피아노-반주명단-2026-09-22.json
행복피아노 명단 10명을 받았습니다.
  새로 들어온 학생 10명
```

### 쓰는 법

```
관리노트 → 설정 → 백업·복원·내보내기 → 「피아노 반주(MR) 연동」 → 학생 명단 내보내기
반주    → python3 catalog_cli.py roster 명단.json   (또는 POST /api/roster)
```

## 3. 번들 판매 — 같은 키 한 장

### 제품 문자를 'K' 로 본다

관리노트 라이선스에는 제품이 셋 있다.

| 문자 | 제품 | 어디서 열리는가 |
|---|---|---|
| `A` | 통합 | 학원 관리노트 · 피아노 관리노트 |
| `M` | 학원 전용 | 학원 관리노트만 |
| `K` | 피아노 전용 | 피아노 관리노트만 |

반주(MR)는 피아노 학원 제품군의 기능이므로 **피아노 관리노트와 같은 문을 쓴다.**
그래서 통합키(`A`)와 피아노키(`K`)는 열리고 학원 전용키(`M`)는 안 열린다.

새 제품 문자를 하나 더 만들 수도 있었지만 그러면 **이미 발급된 `A` 키가 반주를 못
연다.** 번들의 의미가 없어진다. 지금 방식은 `src/core/license.js` 를 **한 줄도 고치지
않으므로** 이미 판 키가 위험해지지 않는다.

### 자바스크립트 규칙을 그대로 옮겼다 — 그리고 여기서 한 번 크게 틀렸다

`piano_mr/license.py` 는 새 규칙이 아니라 이식본이다. salt·문자표·해시식이 한 글자만
달라도 **이미 팔린 키가 죽는다.**

처음 이식했을 때 피아노 관리노트의 학원명 방식 키가 안 맞았다.

```
AssertionError: 행복피아노학원
assert '4EUY-C4MA-X6J9' == 'YY79-JDHF-MCGJ'
```

원인은 자바스크립트의 수 연산이었다. 원본은 `Math.imul` 이 아니라 **그냥 `*`** 를 쓴다.

```js
h1 = ((h1 ^ c) * 16777619) >>> 0
```

- `^` 의 결과는 **부호 있는** 32비트다 → 피연산자가 음수가 된다
- `*` 는 **float64 곱**이라 2^53 을 넘으면 **정밀도가 깎인다**
- `>>> 0` 이 그 깎인 값을 uint32 로 되돌린다

파이썬의 정확한 정수 곱으로 쓰면 값이 달라진다. 그래서 `ToInt32` / `ToUint32` / float64
곱을 그대로 흉내 냈다.

**무작위 696건(체크섬 300 · 학원명 200 · 자기검증 200)을 node 와 대조해 불일치 0건.**
한글·영문·숫자·기호 섞인 학원명까지 포함한다. CI 가 매번 돌린다 — 그리고 node 가 없어
**건너뛰면 CI 를 실패시킨다.** 제일 중요한 검사가 조용히 skip 되는 게 제일 나쁘다.

### 무엇에 키를 요구하는가

| | 키를 보는가 |
|---|---|
| **PDF 업로드** | **본다** |
| 카탈로그 제작 · 화성 확인 화면 | 안 본다 |
| 발표회 운영 화면 | 안 본다 |
| 플레이어 · **집 연습 링크** | **안 본다** |

**PDF 업로드만 보는 이유.** 지시서 8.1 에 따르면 이 제품에서 돈이 나가는 경로는
OMR 하나뿐이다. 인증되지 않은 설치본이 남의 크레딧을 태우면 안 된다.

**집 연습 링크를 안 보는 이유.** 지시서 ⑤-10 이 「설치·로그인 없이 재생」이라고 못
박았다. *"발표회 3주 전 거실에서 학부모가 보는 이 장면이 실제 구매 동기다."*
그 장면에서 학부모에게 인증키를 물어볼 수는 없다.

막혔을 때 화면이 이유를 말한다.

> **PDF 올리기가 잠겨 있습니다.** 인증키가 없습니다
> 관리노트와 같은 인증키를 쓰시면 됩니다. 반주만 잠기고 발표회 운영·집 연습 링크는
> 인증 없이 그대로 됩니다.

### 학원명은 명단이 알려 준다

피아노 관리노트의 **학원명 방식** 키는 검증에 학원명이 필요하다. 반주 쪽은 그걸
따로 물을 필요가 없다 — **명단 파일에 학원명이 들어 있다.**

```python
def test_the_academy_name_for_a_name_based_key_comes_from_the_roster(client, monkeypatch):
    monkeypatch.setenv(lic.ENV_KEY, lic.piano_key_for_name('행복피아노학원'))
    assert client.get('/api/license').json()['ok'] is False    # 아직 명단이 없다
    client.post('/api/roster', files={'file': (...)})           # 명단을 받으면
    assert client.get('/api/license').json()['ok'] is True      # 열린다
```

### 키는 파일이 아니라 환경변수에 둔다

```bash
export MR_LICENSE_KEY=ALAB-CDEF-XYEV
export MR_ACADEMY=행복피아노학원        # 학원명 방식 키일 때만 (명단이 있으면 생략 가능)
```

카탈로그 디렉터리를 통째로 복사해 옮길 때 인증까지 따라가면, 키 한 장으로 여러 학원이
쓰게 된다.

## 4. 교차 시험을 양쪽에 손으로 쓰지 않았다

이 단계의 검사는 전부 **한쪽이 실제로 만든 것을 다른 쪽이 읽는** 방식이다.

| 무엇 | 어떻게 |
|---|---|
| 명단 형식 | node 로 `buildRoster` 를 **진짜 실행**해서 나온 파일을 파이썬이 읽는다 |
| 인증키 규칙 | node 로 `checksumOf`·`generateKey`·`verifyKey` 를 **진짜 실행**해서 답을 대조 |

양쪽에 손으로 쓴 fixture 를 두고 맞춰 보면, 한쪽 형식이 바뀌어도 **둘 다 초록인 채로
현장에서만 깨진다.**

## 5. 아직 안 된 것

| 항목 | 상태 |
|---|---|
| 명단을 자동으로 주고받기 | **안 한다** — 파일로 옮긴다. 두 제품이 다른 곳에 설치되고, 둘 다 오프라인이 전제다 |
| 연습 기록을 관리노트로 되돌리기 | 미착수. 지시서에 없고, 되돌리려면 반주 쪽이 학생 데이터를 더 들고 있어야 한다 |
| 학원이 여럿인 설치본 | 계정을 문자열 하나로만 다룬다. 한 학원 한 대가 전제 |
| 14일 체험 기간 | 관리노트에는 있지만(`TRIAL_DAYS`) 반주에는 넣지 않았다. 업로드만 잠기므로 체험이 따로 필요하지 않다 |
